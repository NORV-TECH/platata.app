# T2 — "3.500 productos ya incluidos" (the built-in product lists and the download gate)

Checked against code at commit **6736ddfb**. Paths under `app/src/main/java/com/example/`. Counts below were measured on the actual files (the bundled assets and the v1.2 download).

## 1. What it really is — TWO different lists
| | **No-barcode catalogue** (bundled) | **Barcode list** (downloaded) |
|---|---|---|
| File | `app/src/main/assets/no_barcode_catalog/catalog_{es,en,pt-br,fr}.db` | `lookup_dictionary.db`, downloaded from GitHub (`dict_download_url`) |
| Rows | **3,523** in each language (same items) | **246,719** rows (v1.2, 31,211,520 bytes) |
| What | bread, fruit, veg, cheese, loose grains, street food, flowers, hardware… with a drawn icon (3,519 SVGs in `assets/no_barcode_icons`) | packaged goods: code, name, brand, size, category, price |
| Used by | the "Sin código" page (T4) | the camera (T1/T3) |
| Language | follows the app language; fallback Spanish (`data/NoBarcodeCatalog.kt:52, 118-124`) | ONE file for every country, names are Spanish (scraped from Colombian shops) |

- "3.500 productos" = the **no-barcode** catalogue (3,523). No pharmacy items in it (searched "aspir", "acetam": none).
- The barcode list by GS1 prefix (country of the brand owner, not where it is sold): Colombia 770/771 **92,371**; US/CA UPC 45,601; in-store codes 29,123; books (ISBN) 19,357; Mexico 5,555; Brazil 2,879; Chile 1,846; Panama 1,485; Argentina 965; Peru 358; Ecuador 173; other 35k. 21,234 rows are tagged pharmacy (10,540 Colombian). 125,060 rows carry a price — all in **Colombian pesos** (e.g. a 789 Brazilian code "Ponqué Panettone" 25.200).
- ~6,100 rows have 9, 10, 11 or 14+ digits; the camera only accepts 8/12/13 (`ScannerScreen.kt:132`), so those can never be found.
- Who: owner phone and employee phone download it (once per phone). Counter tablet never needs it (scans the shop's own catalogue). Retail and Pharmacy identical (`RetailRules.needsProductDictionary = true`).

## 2. How a scan of a known barcode fills the form
`ScannerScreen.kt:154-215`, `data/ProductLookupRepository.kt:167-177`
- Looks up every spelling of the code (12↔13 digits with a leading 0; EAN-8 never padded) (`data/BarcodeFormats.kt:81-91`).
- **Name** = brand + product name + size, cut at **40 characters** (`ScannerScreen.kt:675-683`) — shown **read-only and greyed** (`:411-422`).
- **Category** = the list's `retail_cat_*` key matched to the shop's seeded category in es/en/pt (`ScanCartScreen.kt:284-308`); when it matches, the category picker is not shown at all.
- **Price is never filled.** The list's price is offered as a chip "Sugerido $ 14.890" **only in Colombia** (`data/PriceSuggestions.kt:57-66`); elsewhere the slot reads "Sin precio sugerido".
- If the shop already has that barcode with a price, nothing is asked: it goes straight into the sale.

## 3. Setup before the demo / the download gate
- Creating a Tienda/Farmacia **requires** the barcode list: after Google sign-in the app shows the download page; "Ahora no" creates nothing and returns to the start (`ui/pos/WorkspaceActions.kt:272-288`, `ui/navigation/OnboardingNavGraph.kt:399-445`, `ui/pos/DictionaryDownload.kt:212-215`).
- Existing shop without the list (restore, reinstall, 2nd phone): Scan tab banner + the page opens by itself once per launch (`ui/app/PlatataApp.kt:869-884`).
- Nothing downloads before the "Descargar" tap (`DictionaryDownload.kt:82-114`). WorkManager, needs a connection, resumes, keeps going in the background; thin top strip "Descargando base de datos 37%" (`PlatataApp.kt:808-831`).
- **Demo phones: set the phone language to ENGLISH or download over Wi-Fi only after checking the size shown** — see problem 1.

## 4. Country differences
- No-barcode list: same items everywhere, translated (es for all Spanish countries, pt-br for BR, en for US/CA). Default weight unit Libra in CO only, Kilogram elsewhere (`NoBarcodeCatalog.kt:259-274`).
- Barcode list: same file everywhere; strongest in Colombia; names Spanish in every country (BR and US shops see Spanish names they cannot edit).
- Suggested price chip: Colombia only.

## 6. Demo path (Colombia, owner phone, language set to English if problem 1 is not fixed)

2. Download page shows size → **Descargar** → bar to 100% → shop created → Ready → Continuar.

## 7. UX/UI problems (verified)
1. **Spanish and Portuguese phones download a 606 MB file.** `dict_download_url` is v1.2 in `res/values/strings.xml:3386` but **v1.1** in `values-es:3287`, `values-pt-rBR:3286`, `values-fr:3302`; a HEAD of v1.1 answers Content-Length **635,781,120** (v1.2: 31,211,520). The page then shows "Tamaño: 606 MB" and the free-space check only demands 96 MB (`ProductLookupRepository.kt:70-71`). Fix: one URL marked `translatable="false"` in values only. — **BLOCKS A DEMO**.
2. The picker says "3.523 productos **con código**" next to a barcode icon, but 3,523 is the no-barcode catalogue; the barcode list is 246,719 rows and is a download, not "ready" (`values-es/strings.xml:1622`). Fix: "3.500 productos sin código + 240.000 códigos de barras (descarga)". — small (marketing claim).
3. The download page always says "Creando tu negocio…" and the cancel dialog says "Aún no se ha creado tu negocio", also when an EXISTING shop opens it from the banner or the launch gate (`DictionaryDownloadScreen.kt:124, 237`). Fix: title/dialog by `hasPendingBusinessDraft()`. — small.
4. Names from the list are Spanish in every country, cut mid-word at 40 chars, brand often doubled ("FRESCAMPO Nuggets de pollo FRESCAMPO apanados (30"), and the field is locked (`ScannerScreen.kt:411-422, 675-683`). A Brazilian or US shop cannot fix them. Fix: let him edit the name (keep the code), or drop the brand when it is already in the name. — BLOCKS A DEMO in BR/US (Spanish names on screen).
5. The launch gate (`PlatataApp.kt:874-884`) has no device-role check: a counter tablet of a retail shop (which never downloads) would be sent to the download page at every launch. Possible — verify on a paired tablet. Fix: skip for `DeviceRole.MAMAPOS`/`KDS`.
6. Top strip label "Download items database" (en) is a command, not a status; colour #6E6E73 on #1C1C1E is hard to read (`PlatataApp.kt:808-824`, `scan_dict_downloading`). Fix: "Downloading product list" in white.
7. Some list rows are in the wrong category ("Picadora de verduras" tagged dairy, a kitchen scale tagged bakery) — data quality of the file, not the code. Fix in the data build.
