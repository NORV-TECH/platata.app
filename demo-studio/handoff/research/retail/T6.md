# T6 — "Inventario" (stock on the Items list)

Checked against code at commit 6736ddfb. Paths under `app/src/main/java/com/example/`.

## 1. What it does, who, where
- Every product on the shop's Items list shows how many are on the shelf, with a coloured word under the number (running low / not counted / not tracked). Tapping the number opens one keypad sheet to say "I bought N" (adds) or "I counted N" (replaces). A sale takes the units off the shelf by itself.
- Owner's phone: panel row "Inventario" → Items list, full access (also "+ Nuevo", categories, item form).
- Employee phone (Mini POS): only if the owner gave the permission "Controlar el stock" (`perm_can_control_stock`). Row "Inventario" on the Scan tab card (`ui/screens/onboarding/MiniPosScanTab.kt:103-115`) → the SAME Items list in STOCK_ONLY mode: numbers tappable, no "+ Nuevo", no "+ Categoría", names not tappable (`sync/ItemsAccess.kt`).
- Counter tablet: no Items / stock screen (none found in `MamaPosScreen`).
- Pharmacy = identical (PharmacyRules has no override; `if (isRetail)` gate covers both).

## 2. Setup before the demo
- A RETAIL (or PHARMACY) business with products (scan or "+ Nuevo").
- Factory default: a product made by scanning / quick-add has its size "not counted" (`stockConfigured = 0`), so it shows "?" + "Sin contar" until someone counts it. A product made in the item form with "Count stock" on and a number typed starts counted (E-18).
- The red "Quedan pocos" state needs a low level. The level is asked right after the FIRST count (step 2 of the sheet, suggested = 20% of the count rounded up, `StockScreen.kt:130-140`).
- For the demo: create Leche entera, Pan tajado, Huevos, Arroz 500 g, Banano (per kg). Count Leche = 3 (level 2 → red), Huevos = 30, leave Pan uncounted.

## 3. Country differences
- Same everywhere. Only units and number marks differ:
  - Unit picker (item form): US/CA list Pound/Ounce/Fluid Ounce; everyone else Kilogram/Gram/**Libra**/Liter/Milliliter/Dozen (`sync/UnitPicker`). "Libra" has no kg/g chips; "Pound" has kg/lb/g chips (`StockScreen.kt:81-115`).
  - Decimal mark of a weighed count follows the currency: CO/CL/AR/EC/BR "1,5", MX/PE/PA/US/CA "1.5" (`formatQty`, `StockScreen.kt:120-128`).
- Price column on the list is money format: CO "$ 4.200", CL "$4.200", MX "$42.00", PE "S/ 4.20", AR "$ 4.200,00", EC "$4,20", PA/US/CA "$4.20", BR "R$ 4,20".

### 4d. A sale moves the shelf — `data/repo/StockStore.kt:76-87`, called once from `domain/usecase/PlaceOrderUseCase.kt:199`
- Every PAID sale (cash, QR, card, fiado) takes `quantity` (or the weight) off each counted, tracked size (`PosDao.kt:1640-1647`, never below 0). Not counted / not tracked rows do not move.
- A cancel or FULL refund puts the goods back, only on the device that rang the sale (`StockStore.kt:107-116`). A PARTIAL refund does not (the refund screen says so: `tx_refund_stock_partial`).

## 5. Demo path (owner phone, ~9 taps)
1. Flag → panel shows "Inventario · 1 queda poco · 1 sin contar". Tap it.
2. List opens on "Quedan pocos (1)": Leche entera "2 / queda poco" in red.
3. Tap the "2" → sheet, "Compré" is on → tap "+12" → "Vas a tener 14 unidades" → "Guardar". Row turns grey "14 unidades"; the red pill disappears.
4. Tap pill "Sin contar (1)" → Pan tajado "?" → tap → "¿Cuántos tienes?" → type 8 → "Guardar" → step 2 shows "Rojo en 2 unidades" → "Guardar".
5. Back → Register (Scan tab) → sell 2 Leche (cash) → back to Inventario: Leche now "12 unidades".

## 6. UX/UI problems
1. BLOCKS A MULTI-DEVICE DEMO — stock only moves on the device that rang the sale. `applySaleToStock` runs inside `PlaceOrderUseCase` on the selling device; the owner phone mirrors a counter-tablet / employee-phone sale through `OrderSyncStore.applyRemoteOrder`, which never calls `sellStock` (no stock code in `data/repo/OrderSyncStore.kt`). The owner's Inventario does not drop for sales made on other devices, and the owner's next reference push (variations are part of it, `ReferenceSyncActions.kt:115`) overwrites the tablet's own number. Fix: decrement on the owner phone when a remote PAID order first arrives (by firestoreId, once), or send the stock move with the order.
2. An employee with "Controlar el stock" counts only into their own phone: `PosViewModel.setStock/adjustStock` (`PosViewModel.kt:1970-1990`) write the local DB, nothing sends it to the owner, and the owner's next push erases it. Fix: send stock writes from a Mini POS to the owner (or block the door on a Mini POS until it syncs). Possible — verify with a two-phone run.
3. Header count includes the 24 ready-made categories: "5 artículos · 29 categorías" on a fresh shop (`RetailMenuScreen.kt:121`, `categories.size`, `getAllCategories` returns every row). Fix: count only categories that hold items (the pills already do).
4. On dot-decimal countries (MX, PE, PA, US, CA) the decimal key types a comma: `onDecimal` always appends "," (`StockKeypadSheet.kt:156-160`) while the key label and the result line use "." → "1,5 lb" above "You'll have 1.5 lb". Fix: append `decimalSeparatorFor()`.
5. Word case mismatch: pill "Quedan pocos (2)" vs row badge "queda poco" (lowercase, singular) (`stock_running_low`). Fix: "Queda poco" capitalised like "Sin contar".
6. The partial-refund note says "Corrige el conteo a mano en Inventario / Fix the count by hand in Stock" (`tx_refund_stock_partial`); English says "Stock", but a shop has no Stock screen any more (E-17). Fix: "in Inventory" (en), matching the panel row.
7. Step 2 ("¿Cuándo queda poco?") can be swiped away; the count is kept but no level is set, so the item can never turn red, with no hint (`StockScreen.kt:600-610`). Small. Fix: keep the suggested level when the sheet is dismissed.
