# T12 — "Palabras de farmacia" (what really differs for a PHARMACY vs a shop)

Checked against code at commit 6736ddfb. Paths under `app/src/main/java/com/example/`.

## 1. What it does, who, where
- **Short answer: a pharmacy is a shop with another name.** `PharmacyRules` is an empty subclass of `RetailRules` (`data/business/PharmacyRules.kt:10`, "distinguished ONLY by identity"); `BusinessRulesTableTest` pins pharmacy == retail on every rule. Same Items list, stock, scan, fiado, invoices, online store, back-room screen, receipts-only printer, notifications, discount ideas, devices and prices.
- The ONLY places the code treats PHARMACY differently (full `grep PHARMACY` of main):
  1. The type picker: a two-option switch "Tienda | Droguería" (Colombia) / "Tienda | Farmacia" (elsewhere) inside the one "Tienda" page (`ui/screens/onboarding/BusinessTypePickerScreen.kt:332-340`).
  2. The picker's button "Continuar con Droguería / Farmacia" (`BusinessTypePickerScreen.kt:390-395`).
  3. The "Tu negocio está listo" card: "Droguería · Colombia · COP" (`ui/screens/onboarding/BusinessReadyScreen.kt:155-157`).
  4. The stored type itself (`BusinessType.PHARMACY`), which other code reads only through the rules.
  5. Analytics: reported as "RETAIL" (`data/business/MarketingTypeNames.kt:15`). An ad campaign word "farmacia" preselects RETAIL, not PHARMACY (`MarketingTypeNames.kt:23`).
- Not in the code (searched "expir", "vencimiento", "receta", "prescri", "lote"): no expiry dates, lot numbers, prescription flag, controlled-drug rules, or pharmacy-only categories/seeds. No separate pharmacy barcode dictionary: one download URL for every shop (`ui/pos/DictionaryDownload.kt`, `work/DictionaryDownloadWorker.kt:80`) — the comment "PHARMACY is a retail shop with another dictionary" in `MarketingTypeNames.kt:11` is wrong.

## 2. Setup before the demo
- Create the business: type page "Tienda" → switch to "Droguería"/"Farmacia" → Continuar. Everything after is the shop setup (barcode list download, Ready → "Escanear mi primer producto").
- Seeds are the shop seeds (`creationSeed = RETAIL`): the same 24 ready-made categories, including grocery ones (es: Bebidas, Snacks, Lácteos, Carnes y Embutidos, Panadería, Cereales y Harinas, Frutas y Verduras, Condimentos, Enlatados, Dulces, Congelados, Aseo Personal, Aseo del Hogar, Mascotas, Licores, Farmacia, Otros, Tabaco, Bebé, Artículos para Bebé, Temporada, Deportes, Papelería, Juguetes). For a pharmacy demo, put products under "Farmacia", "Aseo Personal", "Bebé" (avoid Licores/Tabaco per the brief).

## 3. Country differences (the words)
| Where | CO | other es (MX PE CL EC AR PA, US-es) | pt (BR) | en (US, CA) |
|---|---|---|---|---|
| Switch / button / Ready card (`biz_setup_type_pharmacy(_co)`) | Droguería | Farmacia | Farmácia (CO phone in pt: Drogaria) | Pharmacy (CO: Drugstore) |
| Tab subtitle (`biz_tab_shop_sub(_co)`) | Tiendas y droguerías | Tiendas y farmacias | Lojas e farmácias / Lojas e drogarias | Stores and pharmacies / Stores and drugstores |
| Tile line (`biz_tile_shop_desc(_co)`) | Tiendas, minimercados y droguerías | Tiendas, minimercados y farmacias | Lojas, mercadinhos e farmácias | Stores, minimarkets and pharmacies |
| Shop side of the switch (`biz_pg_shop_store`) | Tienda | Tienda | Loja | Store |
| Ready card for a SHOP (`biz_setup_type_retail`) | Tienda | Tienda | Loja | Retail |
- The rule: `usaDrogueria(pais)` = country "CO" only (`ui/screens/onboarding/BusinessTypeOptions.kt:373-386`); the word follows the country, the language only translates it.
- Everything else (money, card in CO/US/CA only, Pix in BR, fiado, units) is the shop's — see T6–T10.

## 6. UX/UI problems
1. **BLOCKS A DEMO (possible, data)** — the barcode list URL differs by app LANGUAGE: English downloads `v1.2/lookup_dictionary.db`, Spanish, Portuguese and French download `v1.1` (`res/values/strings.xml:3386` vs `values-es:3287`, `values-pt-rBR:3286`). Every Spanish/Portuguese shop or pharmacy gets the older list. Fix: one `translatable="false"` URL in `values/` only, delete the copies.
2. small — The "farmacia" ad word lands on "Tienda" (`MarketingTypeNames.kt:23` → RETAIL), so a pharmacy ad opens the picker with Tienda selected; no "drogueria" word exists. Fix: map "farmacia"/"drogueria" → PHARMACY.
3. small — A pharmacy gets grocery categories (Licores, Tabaco, Carnes y Embutidos, Juguetes…) in its item-form category list (`CategoryChoices.forEditor` shows the 24 seeded rows). Fix: a pharmacy seed set (Medicamentos, Cuidado personal, Bebé, Vitaminas, Primeros auxilios, Otros) — the one place a pharmacy override would pay off.
4. small — English Ready card for a SHOP says "Retail" while the picker said "Store" (`biz_setup_type_retail` vs `biz_pg_shop_store`). Fix: "Store".
5. small — The picker's "what's inside" list shows "Fiado" untranslated in English (`biz_w_fiado` en = "Fiado"; everywhere else English says "Tab"). Fix: "Tab (store credit)".
6. small — `biz_pg_shop_note` ("¿Vendes medicamentos? … con tus nombres / its own labels") promises pharmacy labels that do not exist; it is not drawn today (`nota` is never read), keep it unused or fix the text before showing it.
7. small — The "3.523 productos con código" claim is the same for a pharmacy; whether the list holds medicines cannot be told from the app code (the list is a downloaded file). Verify before saying it in a pharmacy video.
