# S6 — Otras formas de pago, y FIADO (SHOP / PHARMACY)

Commit read: `6736ddfb`. Paths under `app/src/main/java/com/example/`.
Custom wallets (Nequi, Yape, Mercado Pago…) and "Cortesía" are the **same as restaurant S6**. The big shop difference is **Fiado** (sell on credit, "a la libreta"), which exists ONLY for shops and pharmacies (`data/business/RetailRules.kt:15` `fiadoEnabled = true`; `data/FiadoScope.kt`).

## 1. What fiado does, who, where
- The cashier attaches a client and taps "Fiar a Ana": the sale is saved as PAID with the debt written in the same transaction (`ui/pos/CartActions.kt:684-690` → `finalizeOrder`, guards `ui/pos/CheckoutActions.kt:179-190`: needs a client and `canFiar`). Stock moves like any sale. No money enters the drawer.
- **Owner's phone: works.** Counter tablet / waiter phone: the "Fiar" chip is always dim for staff, because `canFiar` has **no switch in Team** (it is read, never set: `ui/screens/team/TeamManagementScreen.kt:1179`, permission list `:1331-1341` has no fiado chip; `CartSheetContent.kt:368-379`). Only the owner signed in on a tablet could fiar there, and that debt would stay on the tablet (open bug `_sim/bugs/open/BUG-F2-…md`: `applyRemoteOrder` carries the order, not the `fiado_debts` row; still true, no fiado code in `data/repo/OrderSyncStore.kt` apply).
- Fiado is NOT in "Más formas": the built-in Fiado row is seeded inactive and has no switch (`SeedStore.kt:99`, CLAUDE.md F-16), and "Más formas" lists only active methods (`CheckoutSheetBody.kt:186,257`). The ONLY door is the Fiar button.
- Collecting the debt (Saldar / Perdonar / Recordarle) is S13.

## 2. Setup
A client with a WhatsApp number (S13). Nothing to switch on. Factory: Efectivo ON, Cortesía ON, QR/Tarjeta off, no custom wallets — same as restaurant.

## 3. Country differences
Same word "Fiado" in es and pt (Brazil also says "fiado"); English "Put on tab" / "Tab". Money format per country. No country logic.

## 4. Screens
- Pay screen bottom section (`CheckoutSheetBody.kt:322-341`): client field "Agrega un cliente a la venta" + the button: no client → "Fiar" | "Fiar" | "Put on tab", dim and inert; client attached → "Fiar a Ana" | "Fiar para Ana" | "Put Ana on tab" (first name only).
- Cart sheet header chip on tablet/waiter (`CartSheetContent.kt:363-405`): blue #007AFF at 40 % (dim) or amber `SumaFiadoAmber` #B07500 when live ("Fiar a Ana").
- Sale complete (`ReceiptOptionsScreen.kt:196-210`, `FiadoSaleLines` :524): "Fiaste $ 18.500" | "Adicionado $ 18.500 ao fiado" | "Added $18.50 to the tab", "a Ana" | "para Ana" | "to Ana", then an amber block (bg #FFF6E5, border #F0DCB0, r12): "AHORA TE DEBE" | "AGORA TE DEVE" | "NOW OWES YOU" + the new balance (owner phone only; omitted elsewhere).
- Register screen and close summary later show "Abonos de fiado" (cash paid on tabs) and "En fiado (sin cobrar)" (S9/S10).

## 5. Demo path (owner phone, CO, 7 taps)
Scan 2 products → "Cobrar $ 18.500" → "Agrega un cliente a la venta" → search "ana" → tap "Ana Gómez" → button turns "Fiar a Ana" → tap → "Fiaste $ 18.500 a Ana / AHORA TE DEBE $ 33.500" → "Nueva venta". Then Mi negocio: Clientes row reads amber "1 te debe · $ 33.500".
Wallet beat (same as restaurant): "Más formas (2)" → "Nequi" → confirm box "¿Viste el pago…?" (PAY-1) → done.
