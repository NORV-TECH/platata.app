# R7 — Pantalla de cocina (Kitchen screen / KDS)

Code checked: /home/claude/suma-plus-android @ d1b7698d (read only). Paths below are under `app/src/main/java/com/example/` unless noted.

## 1. What it does, who, which device
- A tablet in the kitchen shows every open order as a card. The cook taps a card, then "LISTO" to send it out. Cards turn yellow, then red, as they wait.
- Devices: **Pantalla de cocina** (any Android tablet/phone, forced landscape, always dark). Set up from the **owner's phone** ("Tu teléfono"). Orders reach it only over the shop Wi-Fi from the owner's phone (the owner phone is the LAN host; the KDS never talks to the internet). Waiter-phone orders go Firestore -> owner phone -> Wi-Fi -> KDS (already flagged #6).
- Who: cook (taps), owner (sets up).

## 2. Setup before the demo
- Owner phone: business type Restaurant, on the same Wi-Fi as the tablet, app open (it hosts the feed).
- Owner phone: Mi negocio › Configuración › Conexiones › "Impresoras y otras conexiones" › "Conectar una pantalla de cocina" -> settings page -> Guardar -> code (10 chars, e.g. `A1B2C3D4E5`).
- Tablet: fresh install -> "Ya uso Platata" -> "Conectar una tablet o pantalla de cocina" -> tile "Pantalla de cocina" -> type code -> Conectar.
- Defaults (no seed): role "Prepara la comida", all categories, all order types, yellow 7 min, red 9 min, name "Pantalla de cocina" (in the shop's language) if left blank.
- **IMPORTANT for the demo**: the screen shows EVERY order that was never marked ready, from all time (`data/PosDao.kt:1023` `getKdsOrders`: `readyTimestamp IS NULL`, no date limit). A demo shop that already has sales will open the kitchen screen full of old red "CRÍTICO" cards. Start from a fresh business, or bump them all first.
- Products need categories only if you want routing (R8).

## 3. Country differences
- Same everywhere. No money is shown on the KDS. Words follow the tablet's own app language (es / pt-BR / en), not the shop language. Order-type names and "Mesa N" come from the owner's data.
- Time in history: `h:mm a` with the device locale (e.g. "Enviado a las 3:42 p. m.").

## 6. UX/UI problems (verified in code unless "possible")
1. Kitchen floods with old tickets: `getKdsOrders` has no date limit (`data/PosDao.kt:1023`); every paid sale never bumped shows, all red. Fix: only show orders created after the screen was set up (or today), or auto-stamp old ones.
2. "Todo listo · Hamburguesa" marks WHOLE tickets ready, not just that dish (`KitchenDisplayScreen.kt:449-460` calls `markOrderReady(id)` for every ticket containing it) — the fries/drinks on those tickets vanish too. Fix: bump only tickets where every visible line is that dish, or relabel "Listo: pedidos con Hamburguesa".
3. Order note never shown: `cartNote` is sent to the KDS (`sync/SyncHostService.kt:479`) but `KdsTicketCard`/`KdsTicketDetailDialog` never draw it. Fix: show the note under the lines.
4. Add-on round duplicates lines if the first round is not yet ready: the main ticket is rebuilt with ALL items and stays on screen (`SavedTicketActions.kt:277-281`), plus the blue add-on card with the new ones (`:386-393`). Fix: create the add-on card only when the main ticket was already bumped, else just update the main one.
5. Add-on label reads "#ADD-ON #57" in English on every language (`SavedTicketActions.kt:393` + `KdsTicketCard.kt:86`). Fix: store the main label only; the band already says ADICIÓN. (Moot if the header fix replaces the label.)
6. Single-ticket "LISTO" has no undo (`KdsTicketDetailDialog.kt:205-208`; undo bar only for bump-all, `:437-445`). Fix: show the same 5-s "DESHACER" bar after any bump.
7. Crossed-off lines are forgotten when the dialog closes (`KdsTicketDetailDialog.kt:77`). Fix: keep them per ticket while it is on screen.
8. Leave dialog speaks of a phone and a "caja": "Este teléfono deja de ser una caja aquí" (`KitchenDisplayScreen.kt:300-305`, string `out_of_service_leave_body`). Fix: a KDS-specific text ("Esta pantalla deja de recibir pedidos…").
9. Tablet code page points to a path that no longer exists: "Mi negocio › Configuración › Dispositivos" (`connect_device_where`); real path is Configuración › Conexiones › Impresoras y otras conexiones. Fix the string.
10. "El código cambia cada vez" is false for a kitchen screen: its code is fixed (`ConfigureKdsRulesScreen.kt:359-360`). Fix: hide that card for the kitchen kind.
11. Kitchen pairing failure says "Sin conexión a internet" (`ConnectDeviceScreen.kt:95-101,140`) but the KDS pairs over Wi-Fi with the owner phone, internet is irrelevant. Fix: "No encontramos el teléfono del dueño en este Wi-Fi. Abre Platata en él y vuelve a intentar."
12. Every screen row says "Conectada" even if no tablet ever paired (`PrintersAndOtherScreen.kt:155`). Fix: show "Código: …" or real status.
13. Detail dialog normal color is hardcoded white/black (`KdsTicketDetailDialog.kt:58`) — fine visually but breaks the "no inline color" rule; minor.
14. Possible: beep fires for tickets this station filters out (sound uses unfiltered `orders`, `KitchenDisplayScreen.kt:208-217`).
