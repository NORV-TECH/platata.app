# S13 — Clientes (Clients), as seen by a RESTAURANT

Source: /home/claude/suma-plus-android @ d1b7698d (read only). Paths under `app/src/main/java/com/example/`.

## 1. What it does, who, where
- A list of the restaurant's customers (name + WhatsApp, optional ID, address, birthday, notes, custom fields), a page per customer with visits, last visit and every purchase, and a way to put a customer on a sale.
- **Owner's phone**: panel row "Clientes" → list → page → edit/delete.
- **Employee phone (Mini POS)**: More panel row "Clientes · Ver y agregar clientes" (always present, `ui/screens/more/MoreScreen.kt:126-131`). Can add; can edit only with "Editar clientes"; never delete.
- **Any till (owner phone, waiter phone, counter tablet)**: on the pay screen, the grey field "Agrega un cliente a la venta" opens the same list in "pick" mode (`ui/screens/home/CheckoutCustomerField.kt:726-771`).
- Restaurant has NO tab/fiado money here (fiado is retail/pharmacy only) and **points are off** (`data/PointsFeature.kt:28` `ENABLED = false`): no points column, no points dock, no star badge at checkout.

## 2. Setup before the demo
- Nothing to switch on. New restaurant = empty list.
- Seed 6–10 customers with real names and WhatsApp numbers, and attach 2–3 of them to past sales (pay screen → "Agrega un cliente a la venta") so their page shows visits and purchases.
- Factory default: security ON with "protect deleting people" ON (`data/PosDatabase.kt:325` default 1; `SeedStore.kt:135`) → deleting a customer asks for fingerprint/screen lock.

## 3. Country differences
- WhatsApp field is pre-filled with the country dial code (digits, no "+"): CO 57, MX 52, PE 51, CL 56, EC 593, AR 54, PA 507, BR 55, US/CA 1 (`utils/CurrencyUtils.kt:373`). A number is "complete" with ≥ 6 digits after a known dial code, ≤ 15 total (`utils/WhatsappUtils.kt:5-10`).
- Placeholder hint (only seen if the field is emptied): es "Código país + número (ej. 573112345678)" (Colombian example for every Spanish country), pt "(ex. 553112345678)", en "(e.g. 573112345678)" (Colombian example for US/CA).
- ID field label: es "Cédula / NIT" (Colombian terms in every Spanish country), pt "CPF / CNPJ", en "ID number" (`profile_id_number`). See C4.
- Purchase amounts on the customer page use the country money format (S11 §3). Dates follow the app language (`utils/PurchaseDate.kt`).
- Otherwise same everywhere.

## 6. UX/UI problems (verified in code)
- **C1 — No way to take a client OFF a sale.** The pay-screen field only re-opens the picker; nothing sends `assignCustomerToCart(null)` (`CheckoutCustomerField.kt:762-768`, `ui/pos/CustomerFiadoActions.kt:235`). A wrong client stays unless the whole sale is cleared. Fix: an "×" on the filled field.
- **C2 — WhatsApp number shown as raw digits** "573001234567" on the customer page (`CustomerPage.kt:158`). Fix: format as "+57 300 123 4567".
- **C3 — Label + button both say only "WhatsApp"** (`CustomerPage.kt:158-160`), so the page reads "WhatsApp … 573… / [WhatsApp]". Fix: button "Escribir por WhatsApp / Abrir chat".
- **C4 — Colombian ID words in every country**: "Cédula / NIT" for MX, PE, CL, AR, EC, PA; and the number example "573112345678" for every Spanish country and for US/CA English (`profile_id_number`, `crm_whatsapp_hint`). Fix: "Documento / ID" or per-country (RFC, DNI, RUT, CUIT); example from `dialCodeFor()`.
- **C5 — Awkward name label** "Nombre (Nombre preferido)" / "First Name (Preferred Name)" for the only name field, which holds the full name. Fix: "Nombre y apellido / Nome e sobrenome / Full name" (as Team already does).
- **C6 — "transacciones" on the purchases list** ("No hay transacciones registradas…") while the heading says "Compras". Fix: "Todavía no ha comprado nada / No purchases yet".
- **C7 — Accented names sort after Z.** Letter groups use the raw first character and `toSortedMap()` (`CustomerCrmScreen.kt:443-449`), so "Álvaro" sits under "Á" after "Z". Fix: group by the letter without accent (Normalizer).
- **C8 — Restaurant panel row has no count** ("Clientes" alone, `HomeScreen.kt:1656-1663`, retail-only subtitle). Fix: "N clientes".
- **C9 — "Contacto de emergencia" on a restaurant customer** (shared with salons). Possible: hide for restaurants.
- **C10 — "Sold by" can read "Tienda Local"** (hard-coded Spanish default user `ui/pos/PosViewModelTypes.kt:543`, `AuthActions.kt:334`) for sales made after a PIN sign-out on the owner's phone. Possible; fix: store the owner's name or nothing.
