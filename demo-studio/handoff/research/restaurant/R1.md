# R1 — "El menú con IA desde una foto" (menu import from photo / PDF)

Code checked: /home/claude/suma-plus-android @ d1b7698d (sim/usa-canada). Paths below are under `app/src/main/java/com/example/`.

## 1. What it does, who, where
The owner photographs the printed menu (up to 5 photos) or uploads PDFs/photos; the phone reads the text (on-device OCR), sends it to an AI (DeepSeek, one request), and shows a review list. Only ticked rows are written: one category per menu section, one product per dish, sizes as variations, and a bundled stock photo when the dish name matches one of 278 food photos (`utils/MenuImageMatcher.kt`, `assets/menu_images/`).
- WHO: owner only. DEVICE: owner's phone ("Tu teléfono"). Counter tablet / waiter phone / kitchen screen never see it; they receive the finished menu through the reference sync (auto-push, 1.5 s debounce, `ui/pos/ReferenceSyncActions.kt:110-131`).
- Runs in a foreground service (`MenuImportService.kt`) with a notification "Importación de menú en curso", so the owner can leave the app while it reads.
- Side effect worth showing: the AI also proposes cuisine-specific starter add-ons (sauce 4, toppings 6, protein 3, dip 5). They are NOT created as add-ons; they are stored in `app_metadata.cuisine_modifier_overrides` and pre-fill the matching add-on ideas later (R3) (`ui/pos/MenuImportActions.kt:140-163`).

## 2. Setup before the demo
- Business type Restaurant. Menu empty = the register Library shows the import page; menu not empty = review opens in ADD mode (nothing ticked).
- Camera permission (asked on first tap). Android 13+: notification permission asked once per phone, before the camera/picker (`MenuImportDoors.kt:111-121`).
- Internet (AI step). No seeds needed: a new restaurant starts with an empty menu.
- Have a clear printed menu or a 1-5 page PDF. Pages over the cap trigger the "Menú largo" question.

## 3. Country differences
- Flow and screens are the same everywhere. Language: es (CO MX PE CL EC AR PA, US-es), pt-BR (BR), en (US, CA).
- Spanish uses both "carta" and "menú" (see problems). Portuguese uses "cardápio" everywhere in this flow.
- Prices in the review use `formatCurrency` (ICU, `utils/CurrencyUtils.kt:204`; vectors `functions/test-vectors/money-format.json`):
  CO `$ 12.000` (0 dec, nbsp), CL `$12.000` (0 dec), MX `$1,234.50`, PE `S/ 1,234.50`, EC `$1.234,50`, AR `$ 1.234,50`, PA `USD1,234.50`, BR `R$ 1.234,50`, US/CA `$1,234.50`.
- The price-correction box takes 0 decimals for COP/CLP, 2 elsewhere (`ui/components/SumaTextField.kt:38-63`).
- The AI is NOT told the country or currency (prompt `MenuImportService.kt:110-133`); its only price rule is the Colombian one ("29.200" -> 29200). Possible misreads on 2-decimal menus (see problems).
- Cash rounding, tips, card: not involved.

## 5. Demo path (owner phone, empty restaurant, ≤10 taps)
1. Register opens on the empty Library -> tap "Tomarle una foto a la carta".
2. Allow camera (first time only).
3. Tap shutter (page 1); 4. tap shutter (page 2) — thumbnails appear, counter.
5. Tap "OK (2)" -> processing: "Leyendo tu menú…" -> "Consultando la IA…" -> "Organizando tu menú…" (about 1-2 min; cut in the video).
6. Review "Revisa tu menú · 24 artículos encontrados" all ticked -> tap one misread price -> 7. type the right price -> "Guardar".
8. Untick a promo line the AI took as a dish.
9. Tap "Agregar 23 artículos" -> back on the register: snackbar "23 artículos agregados", chips per category, tiles with food photos.
10. (Hand-off) open the counter tablet / waiter phone: the same menu appears there seconds later (reference sync), no action needed.

## 6. UX/UI problems found
1. False hint: "Verificamos 3 veces para mayor precisión…" — the code now sends ONE request (`MenuImportService.kt:137-160`; string `menu_onboarding_phase_ai_hint`). Fix: change to "Esto puede tardar hasta 2 minutos…".
2. Error texts in English for every language: "AI servers are busy right now. Please try again in a minute.", "The AI did not answer within 15 minutes. Please try again.", "The AI returned an empty response.", and raw exception text otherwise (`MenuImportService.kt:162-215`). Fix: string resources + one plain fallback; never show e.message.
3. "Intentar de nuevo" does not retry: it resets to Idle (`MenuOnboardingScreen.kt:81-84`); on the register-origin page Idle closes the page and drops the owner back on the register (`CatalogNavGraph.kt:58-63`). Fix: label it "Volver" or reopen the camera/picker directly.
4. Review subtitle says "encontrados en la foto" even for a PDF upload (`menu_review_build_subtitle`). Fix: "encontrados en tu carta".
5. Review gives no clue the price is tappable (plain bold text, `MenuOnboardingScreen.kt:390-397`); names and categories cannot be corrected at all, and the category of each row is not shown. Fix: pencil icon on price; show category headers; allow name edit.
6. Multi-size dishes: the review shows and corrects only the first size (`representativeMenuPrice`, `MenuImportReview.kt:58-61`; correction goes to variants[0], line 132-140). The other sizes enter unseen, and the dish form can't show them either (R2 problem 1). Fix: list sizes under the row.
7. The AI is not told the shop's country/currency; the only price rule is Colombian ("29.200" -> 29200) (`MenuImportService.kt:110-133`). Possible wrong prices on US/MX/PE ("12.50") or BR/AR ("12,90") menus. Fix: pass currency + decimal rule in the prompt.
8. Spanish word mix in one flow: "carta" (empty page, photo button) vs "menú" (sheet, camera, review); "artículos" vs "productos" ("Agregar productos" title, "Agregar %d artículos" button, "Un producto a la vez"). Fix: pick "carta" + "platos" for restaurants.
9. Camera has no guidance: tips strings `menu_camera_tip_1..4` ("✓ Menú completo dentro del encuadre"…) exist but are never drawn (0 uses). Fix: show them over the preview.
10. Camera "x" to delete a photo is 20 dp and the shutter has no screen-reader label (`MenuCameraScreen.kt:153-166, 189-213`). Fix: 48 dp touch area, contentDescription.
11. "OK (%d)" is English-looking in es/pt. Fix: "Listo (2)" / "Usar 2 fotos" (string `menu_camera_use_photos` already exists, unused).
12. Cancel dialog answers are bare "Sí" / "No" to a negative question "¿Perder tu escaneo?" (`MenuOnboardingScreen.kt:87-99`). Fix: "Descartar" / "Seguir revisando".
13. If the AI ever returns add-on groups, they are copied once PER DISH (a global "Salsas" would become 30 separate add-ons) (`MenuImportActions.kt:207-235`). Today the prompt never asks for groups, so it is dormant; possible. Fix: create each group once and link it.
14. Stock-photo match accepts half the words (`MenuImageMatcher.kt:57`): "Pollo asado" can get the "arroz con pollo" photo. Possible. Fix: raise threshold or show the photo in the review so it can be removed.
15. Import from inside Your Menu ends silently (no "N agregados" note; only the register path announces). `MenuImportActions.kt:58-63`. Fix: same snackbar on Your Menu.
