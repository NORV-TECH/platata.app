# R4 — "Pedido en la mesa" (table order end to end)

Checked against code at commit d1b7698d. Paths under `app/src/main/java/com/example/`.
"ASSUME FIXED" items from the brief are described as done and marked (fixed).

## 1. What it does, who, where
- A table's order is saved as an OPEN ticket (status PENDING, not paid), sent to the kitchen, reopened to add a second round, and charged at the end.
- Owner phone ("Tu teléfono"): Guardar / Enviar a cocina beside Cobrar, with the "Nombre o mesa" pop-up.
- Waiter phone ("Teléfono de empleado"): table chosen in the dining step, then "Guardar" on the pay step.
- Counter tablet ("Tablet de mostrador"): Abiertas tab, one tap opens the ticket to pay (see R9).
- Every device sees the ticket in "Abiertas" (synced through Firestore).

## 2. Setup before the demo
- Restaurant business, a menu, register open ("Abrir caja") on the owner phone.
- Dining options (R5): Mesas ON with a count (e.g. 12). Without Mesas ON the pop-up has no table chips and the waiter cannot pick a table.
- "Enviar a cocina" label appears on the owner phone only when a kitchen screen or an order printer is set up on THAT phone (`ui/PosViewModel.kt:3624`, KDS list is per-device prefs). Otherwise the button says "Guardar".
- For the waiter part: R6 setup. For the kitchen part: a paired KDS.

## 3. Country differences
- Flow identical in every country. Money format only: CO "$ 45.000", CL "$45.000", MX "$450.00", PE "S/ 45.00", AR "$ 4.500,00", EC "$45,00", PA "USD45.00", BR "R$ 45,00", US/CA "$45.00".
- Charging at the end: card only CO (Wompi) and US/CA (Stripe, tip screen only there); BR QR carries the amount; cash rounding on cash sales in CA (5¢), CL ($10), PE (S/0.10 down).
- Words: es "Guardar / Enviar a cocina / Cobrar", pt "Salvar / Enviar para a cozinha / Cobrar", en "Save / Send to kitchen / Charge".

## 5. Demo path (owner phone + waiter phone)
1. Waiter phone: tap 2 dishes → "Cobrar $ 45.000 · 2 artículos".
2. "¿Cómo sale este pedido?" → "Mesas" → "4".
3. Pay step → "Guardar" → (fixed) "Guardado: Mesa 4". Kitchen shows "Mesa 4 · Ana".
4. Owner phone: Ventas › "Abiertas" → card "Mesa 4" → "Agregar ítems".
5. Amber bar "Mesa 4 · Salir"; tap 2 drinks → "Enviar a cocina" (second round to kitchen).
6. "Cobrar $ 55.000" → pay sheet (table already set, no question) → "Exacto · $ 55.000".
7. "¡Venta completada!" → "Nueva venta". Ticket leaves Abiertas on every device.

## 6. UX/UI problems (verified)
1. Waiter phone, adding a round to a reopened table: the cart bar uses `openPayDirect` (`MiniPosSellScreen.kt:340-348`, `:676`), which walks the full flow, so "¿Cómo sale este pedido?" and the table are asked AGAIN; a wrong tap moves the table. Fix: when `loadedSavedOrderId != null`, use the "only missing steps" rule of `openTicketToPay` (`:359-378`).
2. The typed name from "Nombre o mesa" never shows on the Abiertas card: the card ignores `receiptLabel` for non-online tickets (`CartSheetContent.kt:1293-1300`). A ticket parked as "Juan" or "Barra" reads "Cliente (N.° 57)". Fix: title order customer → receiptLabel → "Mesa N" → "#N" (extends fixed item #3).
3. Waiter phone never says "Enviar a cocina": the label needs a KDS in THIS device's prefs (`CheckoutSheetBody.kt:298`, `HardwareActions.kt:118`), which only the owner phone has; same action, two names. Fix: say "Enviar a cocina" on Mini POS/tablet when the shop has a kitchen screen (sync a flag).
4. Owner phone: when the left button says "Enviar a cocina", the snackbar after it still says "Guardado: Mesa 4" (`HomeScreen.kt:1309`). Fix: "Enviado a cocina: Mesa 4" when kitchenTarget.
5. Reopened ticket "Enviar a cocina" on the owner phone gives no feedback at all (`HomeScreen.kt:707-709`, `stayOnTicket = true`). Fix: same snackbar.
6. "Pagar esta orden" is the customer's verb; everywhere else the cashier "Cobra" (`tx_pay_this_order`). Also "Orden abierta" vs tab "Abiertas"/"Pedido" mix. Fix: "Cobrar" and one noun ("Cuenta"/"Pedido").
7. "Nombre o mesa" chips are bare numbers "1 2 3…" in one long scrolling row (`ParkTicketDialog.kt:66-77`) — with 30 tables Mesa 25 needs a long swipe, and no label says they are tables. Fix: wrap into a grid like "¿Qué mesa?", or prefix "Mesa".
8. The pop-up does not preselect the table the sale already has (`ParkTicketDialog.kt:51`, `table = null`). Fix: start with `uiState.selectedTableNumber`.
9. `hasKitchenTarget()` is read once in `remember {}` (`HomeScreen.kt:691`, `:791`): add a KDS mid-session and the footer still says "Guardar" until the screen is rebuilt. Possible. Fix: read it from a flow.
10. Waiter phone has no way to name a ticket when Mesas is off (no "Nombre o mesa" there; only the MANUAL receipt mode name step). Fix: show the same pop-up on Guardar.
