# R5 — "Comer aquí, llevar o domicilio" (dining options)

Checked against code at commit d1b7698d. Paths under `app/src/main/java/com/example/`.

## 1. What it does, who, where
- The owner switches on how orders leave (For Here / To Go / Delivery / Tables, plus his own options like "Terraza"), sets an upcharge per option, the number of tables, and an optional default.
- At checkout the cashier answers "¿Cómo sale este pedido?" and, for Tables, "¿Qué mesa?". The pick rides the order to the receipt, the kitchen ticket and Reports.
- Settings: owner phone only. The question: owner phone (dim pop-up over the pay screen), waiter phone and counter tablet (its own full step before the pay step).

## 2. Setup before the demo
- Factory default: ALL four options are seeded OFF (`data/repo/SeedStore.kt:110-115`, `:346-351`), upcharge 0, Tables has no count. So out of the box nobody is asked anything and no table exists.
- Way in (only door): panel (flag) › Menú › section "OTROS" › row "Opciones de servicio" (`ui/screens/items/YourMenuScreen.kt:110-121`). It is NOT in Configuración.
- Recommended demo setup: Mesas ON with 12 tables, Para llevar ON, Domicilio ON with an upcharge (CO: 3000). "Para aquí" must stay OFF: Mesas and Para aquí cannot both be on (`DiningOptionsScreen.kt:178-186`).
- Optional: "Predeterminada" on Para llevar (then nobody is asked; Tables can never be the default — `sync/DiningDefault.kt`).

## 3. Country differences
- Same everywhere except money format of the upcharge and the field example "(ej. %s)" = `exampleAmount()` = 5000 or 5.50 in the local format (`utils/CurrencyUtils.kt:303`).
- Upcharge examples (from `functions/test-vectors/money-format.json`): CO "$ 3.000", CL "$3.000", MX "$30.00", PE "S/ 3.50", AR "$ 300,00", EC "$1,00", PA "USD1.00" (no space, see problems), BR "R$ 3,00", US/CA "$3.00".
- Words: es "Para aquí / Para llevar / Domicilio / Mesas"; pt "Para comer aqui / Para viagem / Entrega / Mesas"; en "For Here / To Go / Delivery / Tables".

## 5. Demo path (owner phone, CO)
1. Flag › Menú › "Opciones de servicio".
2. Mesas switch ON → type 12 → Guardar.
3. Para llevar ON. Domicilio ON → pencil → 3000 → Guardar.
4. Back to the till, tap 2 dishes, "Cobrar $ 45.000".
5. Dim pop-up "¿Cómo sale este pedido?" → tap "Domicilio" → total becomes $ 48.000, link shows the option.
6. Tap the link → pop-up again → "Mesas" → "¿Qué mesa?" → 4 → link "Mesa 4", total back to $ 45.000.
7. "Exacto" → "¡Venta completada!".

## 6. UX/UI problems (verified)
1. System options are stored with ENGLISH names ("For Here", "To Go", "Delivery", `SeedStore.kt:111-114`) and several places print the raw name: pay link `CheckoutSheetBody.kt:262-268` ("To Go" in a Spanish app), kitchen ticket `ui/components/KdsTicketCard.kt:169` ("TO GO"), receipt line `ui/PosViewModel.kt:4720` + `ReceiptBuilder`, Reports breakdown `ReportsScreen.kt:348`, Abiertas detail `OpenOrderMoneyRows.kt:103`, tablet chips `CartSheetContent.kt:1001`. Fix: one `diningDisplayName(option)` helper (systemKey → string) everywhere, and store the localized name on the order.
2. Breakdown row always prefixes "Domicilio ·": "Domicilio · To Go", "Domicilio · For Here" (`CheckoutBreakdownScreen.kt:227`, string `checkout_desglose_delivery`). Fix: show just the option name.
3. "+ Nuevo" dialog upcharge field has no money filter (`DiningOptionsScreen.kt:369-376`, `:391` raw `toDoubleOrNull`): in CO typing "3.000" (as the hint "ej. $ 5.000" suggests) saves $3; in AR/BR "1,50" saves 0. Fix: use `filterDecimalInput` like the edit field (`:270`).
4. The gate never shows the upcharge (`CheckoutSheetBody.kt:1240-1257`): the cashier picks "Domicilio" without seeing "+$ 3.000". Fix: second line "+ $ 3.000" on options with an upcharge.
5. Table grid gives no sign of which tables already have an open ticket (`CheckoutSheetBody.kt:1196-1210`): easy to open two tickets for Mesa 4. Fix: mark taken tables (from open orders' tableNumber).
6. Only door to the setting is Menú › OTROS (`YourMenuScreen.kt:110-121`); not in Configuración. Fix: add a hub row "Opciones de servicio" (restaurant).
7. Row subtitle "Para aquí, para llevar, a domicilio" (`settings_dining_options_subtitle`) never mentions Mesas, the main restaurant use. Fix: "Mesas, para llevar, domicilio".
8. Mesas and Para aquí are mutually exclusive but the screen does not say why until you hit the wall (`:178-186`). Fix: one grey note under Mesas "Reemplaza 'Para aquí'".
9. pt wording mismatch: row "Opções de atendimento" vs page title "Opções de serviço" (values-pt-rBR). Fix: one word.
10. The phone gate has no cancel or back on its options list (`DiningGate`, `onBack = null`); only system back. Possible dead end for a user who opened Cobrar by mistake. Fix: small "Volver" text under the options.
11. Panama money prints "USD1.00" (no space, ISO code) — `money-format.json` PA. Fix: "$1.00" or "B/. 1.00" (not dining-specific).
