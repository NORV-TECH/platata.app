# R9 — "Tableta en el mostrador" (counter tablet, MamaPos)

Checked against code at commit d1b7698d. Paths under `app/src/main/java/com/example/`.

## 1. What it does, who, where
- An Android tablet becomes the shop's counter register ("Tablet de mostrador"). It is landscape, always light, locked behind a profile + PIN, and sells, opens tables from "Abiertas" and charges them.
- Owner phone creates the register and shows a code; the tablet types the code. Cashiers/waiters sign in on the tablet with their PIN.

## 2. Setup before the demo
- Owner phone: register open ("Abrir caja"). A tablet can NEVER open the register; a closed register shows "Caja cerrada" for everyone, owner included (`MamaPosScreen.kt:425-433`, `:1525-1560`).
- A connection for the tablet: outside US/CA the first device is included, a second device needs a paid connection (see R6). US/CA: free.
- Employees with PINs (Equipo). The owner appears on the profile list too; an owner with no PIN enters with no PIN (`:441-444`).
- Both devices need internet for pairing (cloud `pairViaCloud`). The code screen also starts the shop Wi-Fi host.
- For "Enviar a cocina" on the tablet: a kitchen screen or order printer configured ON THE TABLET (see problems).
- Optional: open tables saved earlier (R4) so the tablet opens on "Abiertas".

## 3. Country differences
- Same flow everywhere; money format only (CO "$ 45.000", BR "R$ 45,00", US "$45.00", PA "USD45.00"…). Card button only CO/US/CA; Stripe Tap to Pay needs Android 13+ with NFC on the tablet itself; BR Pix QR with the total; cash rounding CA/CL/PE.
- Words: es "Tablet de mostrador", pt "Tablet do balcão", en "Counter tablet"; "POS BLOQUEADO" | "PDV BLOQUEADO" | "POS LOCKED".

## 6. UX/UI problems (verified)
1. "Siguiente" on "Nombra esta tablet" navigates BEFORE the connection check runs (`CounterRegisterNameScreen.kt:68-73`; check inside `RegistersActions.kt:149-185`). When a connection is needed, the code page shows a spinner forever (or the previous register's code from `lastCreatedToken`) behind the "need a connection" dialog. Fix: navigate only after the register was created.
2. Tablet hint "Lo ves en … Mi negocio › Configuración › Dispositivos" (`connect_device_where`): the row is called "Conexiones" now, and the code is found again by tapping the tablet row there (`CounterRegisterDetailScreen.kt:26`). Fix: "…Configuración › Conexiones › tu caja".
3. Tablet "Enviar a cocina" pill needs a KDS or order printer configured on the TABLET (`MamaPosScreen.kt:927-928`, per-device prefs); the shop's kitchen screen lives on the owner phone, so the pill basically never shows and the pay block says "Guardar". Fix: base it on the shop having a kitchen screen.
4. Profile page has no visible back/exit (`:388-488`), only system back; and a closed register is only discovered after tapping a face and typing a PIN. Fix: show "Caja cerrada" on the profile page itself, add a back icon.
5. Role line falls back to "Cajero" for every non-owner (`MamaPosScreen.kt:88-91`), wrong for a waiter. Fix: no line, or the job title only.
6. Locked screen and profile/PIN pages hard-code `Color.White` (`:290`, `:393`, `:531`), against the token rule (tablet is always light so it looks fine). Low.
7. Tablet amber bar opens to PAY even when the cashier only wants to add a round; adding needs a tap on the tiny "›" label or the dimmed catalog (`:956-990`, `:1281`). Fix: "Agregar" button in the bar.
