# R10 — Imprimir comanda y recibo (Kitchen order slip + receipt printing)

Code: /home/claude/suma-plus-android @ d1b7698d (read only). Paths under `app/src/main/java/com/example/`. Also `docs/PRINTERS.md`.

## 1. What it does, who, which device
- A restaurant can save TWO printers: one for **Recibos** (customer receipt + cash drawer) and one for **Pedidos de cocina** (the "COMANDA" slip). Bluetooth (paired in Android) or Wi-Fi/network (raw TCP port 9100, private IP only). ESC/POS, 32 characters wide.
- Set up by the owner on the **owner's phone only** (Printers page is owner-only, `ui/navigation/RegisterNavGraph.kt:117-135`). Printer settings are per device and per business (`data/HardwarePrefs.kt`), so in practice only "Tu teléfono" prints. The counter tablet and waiter phone have no page to add a printer (see problems).

## 2. Setup before the demo
- An ESC/POS printer: Bluetooth paired in Android settings, or on the same Wi-Fi with a private IP (e.g. 192.168.1.50:9100).
- Owner phone: Configuración › Conexiones › "Impresoras y otras conexiones" › "Conectar una impresora" -> chip "Recibos" or "Pedidos de cocina" -> tap the printer.
- No printer seeded. Drawer connector `drawer_pin` default 0 (pin 2).
- Auto cash-drawer after a sale needs `cash_drawer_enabled` = true, which NO screen sets today (see problem 1).

## 3. Country differences
- Money uses `formatCurrency` (same as screen): CO `$ 45.000` (no decimals, dot groups; the space is a no-break space), MX `$45.00`, PE `S/ 45.00`, CL `$45.000`, EC `$45,00`, AR `$ 45,00`, PA `USD45.00`, BR `R$ 45,00`, US/CA `$45.00` (`functions/test-vectors/money-format.json`).
- Cash rounding (CA nearest 0.05, CL nearest 10, PE down to 0.10, `utils/CashRounding.kt:47-52`): a cash receipt prints "TOTAL" exact, "Redondeo en efectivo +$x", "Total en efectivo" (`PrintManager.kt:289-293`).
- Card line below the total (CO Wompi, US/CA Stripe only): "VISA *4242 · 1 cuota" with ASCII `*` (`PrintManager.kt:305-306`).
- Tips (US/CA): the paper receipt has no tip line (no tip field in `ReceiptPrintData`, `PrintManager.kt:20-51`).
- Words: printed labels in the app language: "COMANDA" | "COMANDA" | "ORDER TICKET"; "MESA 4" | "MESA 4" | "TABLE 4"; "Descuento", "Impuesto", "TOTAL", "Cambio" | "Troco" | "Change Due".

## 5. Demo path (owner phone + 2 printers)
1. Configuración › Conexiones › Impresoras y otras conexiones › "+ Conectar una impresora".
2. Chip "Recibos" › tap the Bluetooth printer -> "Impresora agregada".
3. "+ Nuevo" › chip "Pedidos de cocina" › "Buscar en mi Wi-Fi" › tap 192.168.1.50.
4. Tap the receipt printer › "Imprimir página de prueba" -> slip "PÁGINA DE PRUEBA … Si puedes leer esto, la impresora funciona."
5. Sell 2 Hamburguesas, Mesa 4 › "Enviar a cocina" -> COMANDA prints in the kitchen.
6. Reopen Mesa 4 › add 1 Limonada › "Enviar a cocina" -> COMANDA with only "1x Limonada".
7. "Cobrar" › Efectivo › exact -> receipt prints (note problem 2: kitchen prints again).
8. Sale complete › "Imprimir otra vez".

## 6. UX/UI problems (verified in code unless "possible")
1. Automatic cash drawer never opens: `hasCashDrawer()` reads `cash_drawer_enabled` (`ui/PosViewModel.kt:4841-4842`) and nothing in the app ever writes it (only readers). Also hides the "Abrir cajón" per-payment switch (`ui/screens/settings/PaymentMethodsScreen.kt:105,348`). `docs/PRINTERS.md` bench step 5 would fail. Fix: treat "receipt printer saved" (or the drawer test answered Yes) as drawer on, or add the switch.
2. Paying a ticket that was already sent reprints the WHOLE comanda in the kitchen: `finalizeOrder` prints `buildPrintItems(currentState.cart)` with no "already sent" filter (`CheckoutActions.kt:528,563-572`). Fix: on pay, print only lines not yet sent (`isSentToKitchen`), or nothing for a settled ticket.
3. Paper receipt ignores the Receipts settings: no header/footer message, phone, address, website, and it uses the business name, not "Nombre de la tienda" (`PrintManager.kt:260-311`), while the Receipts page preview shows them. Fix: pass `ReceiptConfig` into `buildReceipt`.
4. Comanda has no order note, waiter or customer name (`OrderPrintData`, `PrintManager.kt:53-63`); a long dish name is cut at 32 chars (`:327`). Fix: add note + waiter; wrap long names.
5. Counter tablet and waiter phone cannot have a printer: the Printers page is owner-only (`RegisterNavGraph.kt:117-123`) and printers are stored per device. A tablet sale prints nothing. (Related to flag #11 but different.) Fix: allow the printer page on the tablet, or route tablet prints to the owner's printers.
6. Order-type names print in English ("To Go", "For Here") because the stored name is the seed's (`data/repo/SeedStore.kt:111-114`, `CartActions.kt:729`). Fix: localize by `systemKey` at print time.
7. Possible: accents and the no-break space may print as wrong characters: text is encoded ISO-8859-1 but no code page is selected after `ESC @` (`PrintManager.kt:231,310,335`); many printers default to PC437 (0xA0 = "á", so `$ 45.000` -> `$á45.000`; "ñ"/"é" garbled). Fix: send `ESC t 16` (WPC1252) or map to the printer's page. Needs bench check.
8. Printer list does not say which printer is Receipts vs Kitchen; two Wi-Fi printers are both "Impresora Wi-Fi" (`PrinterListScreen.kt:105-119`, `PrinterAddScreen.kt:140`). Fix: show "Recibos"/"Pedidos de cocina" under the name; default Wi-Fi name by kind.
9. No test print for the kitchen printer (test section only for `receipt`, `PrinterDetailScreen.kt:25-26`). Fix: "Imprimir comanda de prueba".
10. "Agregar impresora" asks for Bluetooth permission on open even if the owner wants a Wi-Fi printer (`PrinterAddScreen.kt:118-120`). Fix: ask only when the Bluetooth part is used.
11. Bluetooth list shows every paired device (headphones, car) (`HardwareViewModel.kt:88-91`). Possible confusion. Fix: filter by printer device class, or label "Elige tu impresora".
12. US/CA tip never printed on the paper receipt (no tip field). Possible mismatch with the card total. Fix: add "Propina" line.
13. "Wi-Fi"/"Bluetooth" tags are hard-coded English (`PrinterAddress.kt:17-18`) — OK as brand words; minor.
14. Every printer row says "Conectada" regardless of reachability (`PrintersAndOtherScreen.kt:155`). Fix: "Guardada" or a live check.
