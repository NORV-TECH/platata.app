### 4c. What each rule does on the kitchen tablet (`ui/screens/kds/KitchenDisplayScreen.kt:140-177, 349-364`)
- Role "Revisa y despacha" (EXPEDITOR): sees every order and every line.
- Role "Prepara": order types filter whole tickets (`kdsDiningRuleShows`); categories filter LINES inside a ticket (`sync/KdsCategoryFilter.shows`). Both "fail open" (unknown = show).
- Minutes: card colors (R7). The tablet's name is not shown on the tablet any more (`:280-281`).

## 5. Demo path (owner phone; tablets already paired as in R7)
1. Conexiones › Impresoras y otras conexiones › tap "Editar" on "Cocina".
2. Tap "Configuración de la pantalla de cocina".
3. Untick "Bebidas"; tap "Guardar".
4. "+ Conectar una pantalla de cocina" › "+ Nuevo" › name "Bar", tick only "Bebidas", yellow 3 / red 5 › "Guardar" › code.
5. Pair tablet 2 with that code (R7 steps 3-4).
6. Sell 1 Hamburguesa + 1 Limonada, "Enviar a cocina": Cocina tablet shows the burger, Bar tablet shows the lemonade.
7. Add-ons: Menú › Modificadores › "Término" › switch "Mostrar en rojo…" on › tick "Sin cebolla" (see problem 1: red will NOT appear on a real tablet today).

## 6. UX/UI problems (verified in code unless "possible")
1. Red add-ons never show on a real kitchen tablet: `kdsImportantModifierNames` is read from the tablet's OWN database (`ui/PosViewModel.kt:1535`, `data/PosDao.kt:68`), and a KDS gets no catalog/add-on groups (pairing sends only rules + tickets, `sync/SyncHostService.kt:409-435`; kitchen feed sends modifier names only, `:501`). Same for "hide on KDS". Fix: send the important (and hidden) names in the kitchen snapshot or the rules payload.
2. Category routing leaves EMPTY cards: a food-only ticket still renders on the "Bebidas" screen with no lines (`KitchenDisplayScreen.kt:371-373` always renders), and turns yellow/red. Fix: drop a ticket whose visible lines are all filtered out (keep it only during the brief re-sync).
3. "LISTO" on one station clears the ticket on ALL stations: readiness is per order (`ui/pos/OrderFlowActions.kt:29-35` -> host -> every KDS). Bar bumps the drink, the burger disappears from the kitchen. Fix: per-station readiness, or at least only let EXPEDITOR/one station bump; document it for the demo.
4. Order-type names are stored English ("For Here", "To Go", "Delivery") and shown raw: checkbox labels here (`ConfigureKdsRulesScreen.kt:299`) and the KDS banner "TO GO" (`KdsTicketCard.kt:169`). Fix: localize by `systemKey` like `DiningOptionsScreen.kt:95`.
5. Dead hint "Mantén presionado para eliminar ítems de una Estación de Preparación." — no long-press exists anywhere on the KDS (`ConfigureKdsRulesScreen.kt:436-441`). Fix: delete the line.
6. Edit page is dark with stock purple Material colors; the create page is light (`ClientNavGraph.kt:69` wraps in `darkColorScheme()`). Same screen, two looks. Fix: remove the dark wrapper.
7. Two radio labels in one row ("Prepara la comida" / "Revisa y despacha pedidos") with weight 1 each squeeze to 3 lines on a 360dp phone (`:194-207`). Fix: stack the two options vertically.
8. Timer −/+ are 36dp touch targets (`:463,473`), below 48dp. Fix: 48dp.
9. Mixed capitalisation: "Nombre de la Pantalla", "Categorías a Mostrar", "Temporizadores de Alerta" vs "Tipos de pedido", "Alerta amarilla". Fix: sentence case.
10. "Expedidor" wording aside, nothing on the tablet says which screen it is (name removed from the top bar, `KitchenDisplayScreen.kt:280`). With two tablets the cook can't tell "Cocina" from "Bar". Fix: small name label in the top bar.
11. Rule changes reach the tablet only on reconnect, and nothing tells the owner (`LanSyncClient.kt:414-416` comment). Possible confusion in the demo. Fix: push rules on save, or say "Se aplica cuando la pantalla se reconecte".
12. Red matching is by option NAME across all groups (`KdsTicketCard.kt:155`): marking "Extra" red in one group makes every "Extra" red. Minor.
13. "Opciones de mesa" in `kds_rules_no_dining` vs the app's "Opciones de servicio". Fix wording.
