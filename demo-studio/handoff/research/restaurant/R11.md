## 1. What it does, who, which device
- When the kitchen taps "LISTO" on the kitchen screen, the order appears in a bell list on the **counter tablet** ("Tablet de mostrador", MamaPos). The cashier taps a green button to open WhatsApp with a ready message to the customer.
- Only the counter tablet has this list (`ui/screens/mamapos/MamaPosScreen.kt:181-190, 1043-1056, 1483-1497`). The owner's phone and the waiter phone show nothing when the kitchen marks an order ready (no reader of `readyTimestamp` in their screens).
- Message: `utils/ReadyOrderMessage.kt:12-22`, string `order_ready_whatsapp`, in the SHOP's language (`business_language`), plus the WhatsApp signature line. Sent with `KdsDispatchHelper.dispatchTicket` (`KdsDispatchHelper.kt:40-53`) = opens `https://api.whatsapp.com/send?phone=<n>&text=…`; the cashier presses Send in WhatsApp.

## 2. Setup before the demo
- Owner phone + kitchen screen (R7) + counter tablet paired, all on one Wi-Fi.
- The order must have a customer attached (`order.customerId`), and that customer must have a phone in `Customer.phoneNumber` — see problem 1: no screen fills that field, so today the message never opens.
- Switch: "Pedido listo" (NotificationKind.ORDER_READY) is ON by default (`sync/NotificationKind.kt`, restaurant list in `data/business/RestaurantRules.kt:86-91`). The tablet reads its OWN device switch (`sync/ReadyPrompt.kt:14`), which nobody can change on a tablet (Notifications page is owner-phone only, `ui/navigation/SettingsNavGraph.kt:135-141`).

## 6. UX/UI problems (verified in code unless "possible")
1. The message never opens for a real customer: `pingWhatsApp` uses `customer.phoneNumber` (`OrderFlowActions.kt:66`), but every customer is created with `phoneNumber = null` and the number in `whatsappNumber` (`ui/pos/CustomerFiadoActions.kt:132`, `ui/screens/customers/CustomerCrmScreen.kt:856-858`). It silently returns. Fix: use `whatsappNumber` when `hasRealWhatsapp`.
2. Orders that came from another device (owner phone, waiter phone) reach the tablet without `customerId` (LAN ready map has no customer, `sync/SyncHostService.kt:601-650`), so even with fix 1 only orders rung on this tablet can be messaged. Fix: send the customer's WhatsApp number (or id) in the ready message.
3. Silent failure: no customer / no number -> the card disappears and nothing happens (`OrderFlowActions.kt:64-68`, panel removes the card at `MamaPosScreen.kt:1491`). Fix: hide/disable the green button when there is no number, or show "Este pedido no tiene WhatsApp".
4. The owner's "Pedido listo" switch does nothing useful: the switch is per phone and the prompt lives only on the tablet, which has no Notifications page (`SettingsNavGraph.kt:135-141`, `sync/ReadyPrompt.kt:13-14`). Fix: sync this one setting to the tablet (owner settings carrier) or move it.
5. Empty list says "Todo listo" (es) — reads as "everything is ready" in a ready-orders panel (`mamaship_empty`). Fix: "No hay pedidos listos".
6. Button says "Texto", not WhatsApp; title "Notificaciones y Entrega" is jargon; label "Order ID" in English (`mamaship_text_btn`, `mamaship_panel_title`, `mamaship_order_id`). Fix: "Avisar por WhatsApp", "Pedidos listos".
7. Tiny UI: 9-10sp text and 28dp buttons inside a 360dp bottom sheet on a tablet (`MamashipNotificationPanel.kt:63,144-163`). Fix: 14sp+ text, 48dp buttons.
8. Owner phone and waiter phone get no sign at all that the kitchen finished an order (no `readyTimestamp` use outside services/KDS). A waiter can't know Mesa 4 is ready. Fix: a "Listo" badge on Abiertas tickets.
9. The message names only "#57" — no table or customer name; with different numbers per device (flag #13) the customer may get a number that matches nothing. Possible.
10. The bell icon has no content description (`MamaPosScreen.kt:1054`). Minor.
