# S23 — Huella para borrar o descontar (Seguridad) — as seen by a RESTAURANT

Code: /home/claude/suma-plus-android @ d1b7698d. Paths under `app/src/main/java/com/example/`.

## 1. What it does, who, which device
- On the owner's phone, sensitive taps ask for the phone's own lock (fingerprint, face, or the phone PIN/pattern — Android's system prompt, `ui/BiometricHelper.kt:20-23`): deleting dishes/categories/options, deleting employees or clients, removing a service charge, opening the business panel (flag), changing the security switches, deleting a business.
- Refunds ask for a 4-digit EMPLOYEE PIN (owner's or a staff member with "Puede devolver") on any device where Security is on (`ui/screens/transactions/TransactionsScreen.kt:1404,1524-1536`).
- "Bloquear la caja después de" (lock after N minutes) is set on the owner's phone and applies to the counter tablet and waiter phones (they go back to the profile screen / PIN pad). The owner's phone itself never auto-locks.

## 2. Setup / factory defaults
- A NEW business: Security ON (`data/repo/SeedStore.kt:134-135`). Switches: Eliminar dispositivos ON, Eliminar datos ON, Eliminar empleados y clientes ON, Descuentos y cargos OFF (`data/SecurityConfig.kt:12-18`). Lock after = 5 minutes (`sync/OwnerSettings`).
- A BRANCH made without "Ajustes de recibo y dispositivo": Security OFF and there is no switch to turn it on (see problems).
- The phone must have a screen lock or fingerprint enrolled, otherwise prompts can't appear (see problems).
- Owner's own PIN is auto-generated (`SeedStore.kt:128`) and visible in Equipo — needed for the refund demo.
- To show the charge prompt: create a service charge (Descuentos y cargos → Cargo) and switch "Descuentos y cargos" ON in Seguridad.

## 3. Country differences
Same everywhere. Language only. The refund screen amounts follow the country money format (CO "$ 75.800", MX "$1,250.00", BR "R$ 62,50", US "$18.65"), but the PIN pad has no money on it.

## 5. Demo path (owner phone, ≤10 taps)
1. Tap the flag (bottom bar) → system fingerprint sheet "¿Abrir configuración?" → touch sensor → panel opens.
2. "Configuración" → "Seguridad": shows "Seguridad ACTIVA", three switches on.
3. Turn "Descuentos y cargos" on → fingerprint → switch flips.
4. Back to selling: add dishes, a "Servicio 10%" charge is on the ticket → in the pay screen tap "Quitar" under the charge → fingerprint sheet → charge struck through.
5. Panel → "Menú" → long-press/delete a dish → fingerprint → gone.
6. Ventas → open a sale → "Devolver" → "Devolver $X" → confirm → PIN pad "Aprobar devolución" → owner PIN → refund booked.
Hand-off (optional): set "Bloquear la caja después de: 1 minuto" → counter tablet returns to the profile screen after a minute idle.

## 6. UX/UI problems (verified)
1. "Eliminar dispositivos" switch does nothing: `protectDeleteTerminals` is written but never read anywhere (only `SecurityScreen.kt:149`, `PosViewModel.kt:885`). Deleting a tablet/printer/kitchen screen is never gated. Fix: gate `deleteTeamPos`/printer/KDS deletes on it, or remove the switch.
2. The charge-removal prompt says "¿Aplicar descuento? / Confirma para aplicar un descuento" when the owner is REMOVING a service charge. `CartSheetContent.kt:884-885,939-940`, `CheckoutBreakdownScreen.kt:83-84,177-178`. Fix: "¿Quitar el cargo?".
3. "Descuentos y cargos — Aplicar un descuento… requiere aprobación": applying/re-applying a discount is never gated (discounts are automatic; `restoreDiscount`/`waiveDiscount` have no prompt, `CheckoutBreakdownScreen.kt:269,283`). Only removing a CHARGE is. Fix: reword to "Quitar un cargo requiere tu huella".
4. Settings row says "Pide huella antes de borrar o dar descuentos" even though the discounts switch is OFF by default. `SettingsHubScreen.kt:251`. Fix: "Pide huella antes de borrar".
5. On a phone with no screen lock, every switch on the Security screen is a dead tap (prompt errors silently; `showNoBiometricDialog` is declared but never set to true). `SecurityScreen.kt:56-59,66,184`. Fix: check `canAuthenticate` first and show that dialog.
6. Deleting a business uses its own BiometricPrompt with a "Cancelar" button and no device-PIN fallback, so a phone with only a PIN/pattern (no fingerprint) can never delete a business, with no message; and the panel closes before the prompt. `HomeScreen.kt:394-396,508-524`. Fix: use `showBiometricPrompt` (it allows device credential) and close the panel on success.
7. A branch created without "Ajustes de recibo y dispositivo" has Security OFF (`SeedStore.kt:199`), the screen says "Seguridad INACTIVA" and offers no way to turn it on; the flag and refunds stop asking. `SecurityScreen.kt:90-128`, `BranchSetupScreen.kt:75`. Fix: seed branches ON, or add the master switch.
8. The flag prompt says "¿Abrir configuración?" but it opens the business panel (Menú, Clientes, Reportes…). `PlatataApp.kt:252`. Fix: "¿Abrir tu negocio?".
9. Status words are shouty and Title-ish ("Seguridad ACTIVA/INACTIVA", "Datos en Riesgo" style). Minor; fix: "Seguridad activada".
