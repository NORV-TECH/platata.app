Code checked: /home/claude/suma-plus-android @ d1b7698d. Paths under `app/src/main/java/com/example/`.

## 1. What it does, who, where
The owner adds, edits and deletes dishes and categories: name, price, category, photo, and which add-ons the dish has. Every change saves by itself (2 s after typing) and reaches the counter tablet and waiter phones by the reference sync (`ui/pos/ReferenceSyncActions.kt:110-131`, debounce 1.5 s).
- WHO: owner only. DEVICE: owner's phone. Two ways in: (a) "Mi negocio" panel > "Menú" > "Tu menú" page; (b) on the register Library, "Editar" mode or a long-press on a dish tile. Counter tablet, waiter phone and kitchen screen have no edit door (`HomeScreen.kt:1953-1957`).
- A restaurant dish form is deliberately short: no stock, no sizes, no unit, no description (`data/business/RestaurantRules.kt:26` `editorHidesStockAndAdvanced = true`).

## 2. Setup before the demo
- Restaurant business with some categories and dishes (easiest: run R1 first). A brand-new restaurant has 0 categories and 0 dishes (no seed menu).
- For the tax checkbox to appear, at least one active tax must exist (`sync/ShopSwitches.showTaxCheckbox`, `ItemsScreen.kt:1363`).
- Optional: Security "protect delete" on, to show the fingerprint before a delete.
- Have a dish photo in the phone gallery (the form picks from the gallery only).

## 6. UX/UI problems found
1. Dishes with sizes are half-editable: a restaurant form has no sizes row (`editorHidesStockAndAdvanced`, `ItemsScreen.kt:1323`), and the one price box writes only to size 1 (`ItemsScreen.kt:772-787`). A "Media / Entera" dish from the AI import shows one price and the second size's price can never be seen or changed. Fix: show a size list with prices for restaurants when a dish has more than one variation.
2. An empty category page is blank (no message, no button except the small "+") (`CategoryItemsScreen.kt:139-174`); the string `your_menu_no_items` "No hay artículos en esta categoría" exists but is unused. Fix: empty state with "Agregar plato".
3. Each row on the category page repeats the category name already in the title: "Sopas • $ 12.000" (`CategoryItemsScreen.kt:162`). Fix: show only price (and photo).
4. Category page and Library show the FIRST size's price only, no "Desde" (`CategoryItemsScreen.kt:149`). Fix: "Desde $X" when there are several sizes (string `items_price_from` exists).
5. Photo: gallery only — no "take a photo" and no way to remove a photo once set (`ItemsScreen.kt:633-646`, `101-152`). Fix: chooser Cámara / Galería / Quitar foto.
6. Wrong noun for a restaurant: "Nuevo Producto", "Crear Producto", "Editar artículo", "Eliminar artículo", "¿Descartar este artículo?" in the same flow (`ItemsScreen.kt:1013-1029, 1390-1411`). Fix: "plato" for restaurants (rules.menuWording), one noun.
7. The two black "+" buttons are 34 dp (`MenuLayoutParts.kt:227-232`, `CategoryItemsScreen.kt:118-129`) — below 48 dp touch size. Fix: 48 dp touch box around the 34 dp circle.
8. "N en uso" on the Adiciones row counts every add-on, including ones on no dish (`YourMenuScreen.kt:65`). Fix: count only linked ones, or say "N adiciones".
9. Empty "Tu menú" invites "Crea una categoría" instead of the AI photo (`EmptyCategoriesTip.kt`); the AI door is only the unlabeled black "+". Fix: show the photo invitation when the menu is empty.
10. Deleting an empty category happens with no confirmation and closes the page (`CategoryItemsScreen.kt:106-111`). Minor. Fix: confirm dialog.
11. No way to reorder categories or dishes (drag not built; `ui/pos/CatalogActions.kt:190-197` comment). Fix: drag handles or up/down.
12. AI-read descriptions are saved but a restaurant has no description field to see or edit them (`ItemsScreen.kt:1323-1355`). Possible: decide show or drop.
13. pt words mix: panel "Menu", page "Seu Menu", elsewhere "cardápio" (`workspace_menu_title`, `your_menu_title`). Fix: "Cardápio".
14. Spanish tax line ignores the sales-tax variant (fine) but the "Charge tax" checkbox is default ticked with no hint what tax (`ItemsScreen.kt:1363-1388`). Possible; low.
