# S14 — Equipo y claves (Team and PINs), as seen by a RESTAURANT

Source: /home/claude/suma-plus-android @ d1b7698d (read only). Paths under `app/src/main/java/com/example/`. Main file: `ui/screens/team/TeamManagementScreen.kt`.

## 1. What it does, who, where
- The owner's list of people (waiters, cashiers, cooks). Each person gets an automatic 4-digit **PIN** used to sign in on the counter tablet / employee phone and to approve refunds, plus **permissions** (refund, close the till, remove fees, void items, comp, cancel receipts, edit clients, see reports, add supplier invoices). From an employee's page the owner sends a WhatsApp invite with the shop code and the PIN.
- **Owner's phone only** (business panel row "Equipo"). The PIN is then typed on the **counter tablet** (login: "Elige tu perfil" → "Ingresa tu PIN") and on the **employee phone**.
- The same page hosts the employee-pay switch (S15).

## 2. Setup before the demo
- Factory: the owner is already on the list (name from the Google account, role OWNER, random unique 4-digit PIN, `data/repo/SeedStore.kt:117-131`). Security is ON by default → removing a person asks for fingerprint/screen lock.
- Add 2–3 people (e.g. "Ana Gómez", Cargo "Mesera"; "Luis Pérez", "Cocinero") each with a WhatsApp number.
- To show the invite button the person's phone must be switched on from Connections (S19) and not joined yet (`StaffInviteShare.mayOffer`).
- Every new person starts with NO permissions.

## 3. Country differences
- WhatsApp field is pre-filled with "+" + country dial code (+57 CO, +52 MX, +51 PE, +56 CL, +593 EC, +54 AR, +507 PA, +55 BR, +1 US/CA). Placeholder is always "+1 305 000 0000" (see T6).
- "Agregar facturas de proveedor" etc. same everywhere; "Controlar el stock" is never offered to a restaurant (`rules.offersStockPermission`).
- Invite message (shop's Play link + codes) same structure everywhere, in the app language.
- Otherwise identical in every country.

## 6. UX/UI problems (verified in code)
- **T1 — A new hire's PIN cannot be seen until saved and reopened.** The PIN box reads `employee?.pin`, which is null on the create form, so it says "Aún no hay código" although a PIN was already generated (`TeamManagementScreen.kt:1307` vs `:992-999`). Fix: pass the generated `pin` to `EmployeeCodeRow`.
- **T2 — The owner can block himself.** The ⋮ menu offers "Bloquear" on the owner row (only "Eliminar" is hidden, `:722-750`) and `toggleBlockEmployee` has no guard and no confirm (`ui/pos/EmployeeActions.kt:203-207`). Fix: hide Block for `isOwner`, confirm Block for others.
- **T3 — Leaving the form throws away changes silently.** Back/arrow on the employee form goes straight to the list (`:184-187`, `onCancel` :297), no "discard changes?" (Clients has one). Same for the permission sheet edits. Fix: reuse the dirty-check gate.
- **T4 — A switch that does nothing:** "Agregar facturas de proveedor" is offered, but no screen reads that grant (staff invoice capture is deferred, CLAUDE.md E-06; `canAddSupplierInvoice` has no UI consumer). Fix: hide it like "Controlar el stock".
- **T5 — Every non-owner is labelled "Cajero"** even a waiter or cook (`:647-650`). Fix: show the Cargo only, or "Empleado".
- **T6 — WhatsApp placeholder "+1 305 000 0000" is hard-coded US** for every country (`:1163`), and the field only checks "not blank / not just the code" (no length check, unlike Clients). Fix: placeholder from the country; reuse `isWhatsappComplete`.
- **T7 — Two different delete confirms.** List menu → "Eliminar empleado / ¿Eliminar a Ana…?" + phone-access note; form ⋮ → generic "¿Eliminar? / ¿Estás seguro de que deseas eliminar esto?" without the note (`:1313-1320`). Fix: use `EmployeeRemoveDialog` in both.
- **T8 — Counts disagree:** panel says "2 empleados" (owner excluded, `HomeScreen.kt:1717`), the page says "Equipo (3)" (`team_title` with `employees.size`). Fix: same rule both places.
- **T9 — No way to change or regenerate a PIN** (read-only by design, `:1436`, no other screen found). A leaked PIN cannot be replaced. Fix: "Cambiar PIN" action.
- **T10 — Green "POS connected" dot is always on the owner** and on legacy rows only: it reads old role cross-refs (`hasPos = crossRefs.any…` :541), the owner always has an OWNER cross-ref; the real connection is the "En su celular" badge. Fix: drop the dot or drive it from `StaffPhoneState`.
- **T11 — Mixed wording:** "Propietario" badge vs "Agregarme como dueño"; label "PIN" vs invite "Tu código"; permission chips mix forms ("Devolver" / "Puede dar cortesía"; en "Can refund" / "Edit clients"; pt "Pode cortesia" is ungrammatical); "Cerrar turno" while the till screens say "caja"; PIN hint mentions only "una tablet", not the employee phone. Fix: one style ("Devolver ventas", "Dar cortesías", "Cerrar caja"…), one name for the code.
- **T12 — The PIN travels in plain WhatsApp text and via Copy** (`StaffInviteSection.kt:39-45`, `:84-90`) while the owner's own PIN row deliberately has no copy for safety (`:1441`). Possible inconsistency; Monti to decide.
- **T13 — The monthly pay ask can show colleagues' salaries in a staff PIN session on the owner's phone** (possible): it checks `userRole == OWNER` only (`HomeScreen.kt:1341`, `:253`), which CLAUDE.md says stays OWNER during a non-owner PIN session. Fix: use `ReportsAudience.isOwnerView`.
