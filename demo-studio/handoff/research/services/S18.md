# S18 — Combos (SERVICES)

Code read at commit `17d519ac`. Paths under `app/src/main/java/com/example/`. Read with restaurant/S18.md (combo engine, cart, receipt) and retail/S18.md (shops have none). Only what is different for services is here. Nothing was run on a phone.

## 1. What it does, who, where
- A services "combo" is a **pair (or trio) of named services** sold together, with an optional % off: "Pedicure + Manicure −10 %". It is NOT the restaurant's category builder: services use the **deal builder** (`ui/screens/combos/NewDealScreen.kt`), one service per slot, picked by name (`ServicesRules.kt:39-42`: `combosEngineRuns = true`, `combosManagementUiShown = false`, `usesDealWording = true`).
- No fixed combo price: only a % discount (switch, default OFF; chips 5 / 10 / 15 %; box of 2 digits).
- **Build** (owner phone only): Mis servicios › card "Combos", or Gear › "Descuentos y combos" › tab "Combos" (both open the same tab, `DiscountsManagementScreen.kt:300-305`; "+ Nuevo" / "Crear combo" → `Screen.NewDeal`).
- **Sell** (all three tills): owner phone (`HomeScreen.kt`), counter tablet (`MamaPosScreen.kt:1355`), employee phone (`MiniPosSellScreen.kt:516`), through the shared `ProductSheetHost`.
- Same for every trade.

## 2. Setup before the demo
- At least two services with a price. No combo is seeded.
- Best pair: a FIRST service with choices (it is asked properly) and a SECOND service with a single price (see problem 1).

## 3. Country differences
- Same everywhere; only money format ("$ 64.000" CO, "R$ 64,00" BR, "$64.00" US/MX/PA) and the language. Combo discount name on the receipt is written in the shop's language: "<name> — Descuento del combo" (`CatalogActions.kt:637-642`).

## 6. UX/UI problems
1. **Wrong money — the second service is rung at its FIRST stored price, never asked.** `completeComboSelection` adds picked items with `variation = null`, no options, no ASK check (`ui/pos/CatalogActions.kt:634`, `CartActions.kt:191`). A second service with choices ("Cepillado": Corto/Medio/Largo) always rings "Corto"; an "En la caja" one rings its stored price or $0; its paid extras can't be added. Fix: run the second service through `handleProductClick` (choice / options / ask) inside the deal group. Avoid such a service in slot 2 for the demo.
2. small — Two names in one flow: the tab, card, empty state and switch say "Combo(s)", the builder, summary, till bar and buttons say "Oferta" (`deal_*` vs `combo_tab_*`, `services_menu_combos_title`). Fix: pick one ("Combo") for services.
3. small — Combo row description is "1 Uñas + 1 Uñas": it counts items per CATEGORY, and all of a shop's services share the trade category (`DealListScreen.kt:116-124`). Fix: list the service names.
4. small (possible layout) — the combo row puts description (weight 1) + discount badge + status badge + 48dp switch + 48dp trash on ONE line (`ComboRowCard.kt:72-125`); at 360dp the description is left ~20dp and wraps a few letters per line. Fix: badges and controls on a second line (like `SavedRuleCard`).
5. small — Summary title "Oferta creada" before anything is saved (`deal_summary_title`, restaurant problem 1, still open). Fix: "Revisa tu oferta".
6. small — Words for services: "1 · Producto principal", "Vende varios productos juntos…", "Escoge una de las tuyas" (feminine for a service), "TERCERA COSA (OPCIONAL)" in caps unlike the other two overlines; "No está completamente configurada" (feminine) beside "combo". Fix: "1 · Servicio principal", "servicios".
7. small — Pick list shows the lowest price without "Desde" for a service with choices, and the category name when one choice has no price (`NewDealScreen.kt:378-384`); `comboPickPriceText` already exists. Fix: reuse it.
8. small (possible) — Tile pill sits top-left where the services tile draws its trade icon (`ProductCard.kt:208-211` vs `ServiceTileBody`), may overlap. Only on the owner phone (round 3 item 19).
9. small — Blank name saves as the English "Deal" (`NewDealScreen.kt:218`, `fallbackName = "Deal"`).
