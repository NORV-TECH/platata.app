# V6 — Cobrar la cita (turn a booked appointment into a sale)

Code read: /home/claude/app-head @ `17d519ac` (branch sim/usa-canada). Paths under `app/src/main/java/com/example/`.
The pay screen, card, QR and receipt are shared with restaurant/retail and already written up: read `/home/claude/research/restaurant/S3.md` (cash pay screen + Sale complete), `S4.md` (QR), `S5.md` (card + Stripe tip), `S7.md` (receipt). This file says only what is different for SERVICES, and what changed in the code since those files.

## 1. What it does, who, which device
- The appointment (an open ticket with a date) becomes the sale: "Cobrar" on the appointment page loads its service(s), client and fees into the sale and opens the pay screen. The cashier may add more services/products first, then charges cash / QR / card (+ tip in US/CA). The appointment then leaves the Agenda and shows in Ventas as "Pagada".
- Owner phone: Agenda › appointment › "Cobrar" → `viewModel.loadSavedOrderIntoCart(id)` + `requestOpenCartSheet()` + navigate to Home (clears the back stack) (`ui/navigation/ReportsNavGraph.kt:115-123`) → the full-screen pay sheet over the till.
- Counter tablet: same page as an overlay; "Cobrar" puts the ticket in the right-hand cart pane (`ui/screens/mamapos/MamaPosScreen.kt:1512-1517`).
- Employee phone: same route; Home rebuilds `MiniPosSellScreen`, which hears the open-sheet signal and jumps to its PAY step (`ui/screens/onboarding/MiniPosSellScreen.kt:413-427`).
- For services the Ventas screen has no "Abiertas" tab: the Agenda IS the open-ticket list (`ServicesTransactionsScreen.kt:110-114`), so "Cobrar" on the appointment page is the only way to charge a booking.
- Trades: same flow for beauty, pets, vehicles, repairs. Vehicles/repairs (ORDEN) usually charge on the ready date; beauty/pets on the visit. The only trade-dependent rule here is "the picker wins": a SERVICE's pick-one option is a full price, not an add-on (`ui/screens/home/ProductSheetHost.kt:156-158`).

## 2. Setup before the demo
- Register OPEN (S2). Note: charging an appointment is NOT gated by the register (problem 2), so open it on purpose for a clean drawer.
- At least one appointment booked (V4) with a client that has a WhatsApp number (receipt then opens straight to her chat, S7).
- Payment methods as wanted: factory = Efectivo on, Cortesía on, QR off, Card off (S3). Card: CO Wompi keys / US-CA Stripe (S5). BR Pix QR (S4).
- Tips (US/CA only): "Ask for a tip" defaults ON for services (`data/business/ServicesRules.kt` `tipDefaultOn = true`). Outside US/CA there is no tip screen; nothing is seeded for services (the optional "Cargo por servicio" is restaurant-only, MKT3-3). An owner can make one himself: Descuentos y cargos › Cargos extra › "Preguntar al cobrar" (S16).
- Optional: a receipt printer (receipt only — services have no kitchen slips: `printerKinds = RECEIPT_ONLY`).
- If the shop works in 2–3 places (Ajustes › "Dónde trabajas": En el local / A domicilio / Recogen y entregan), see problem 1.

## 6. UX/UI problems (verified in code)
1. **"¿Dónde se hace?" is asked again when charging, and nothing is pre-picked** (shops with 2–3 modes). `loadSavedOrderIntoCart` does not restore the where mode (`ui/pos/SavedTicketActions.kt:804-826`; the pick lives only in memory, `ui/PosViewModel.kt:3524`), so the pay buttons are dead until the cashier taps a chip again (`CheckoutSheetBody.kt:306-308`), and a different tap overwrites the stored mode while the travel fee saved with the booking stays on (possible mismatch). Fix: restore `selectedWhereMode` from `order.diningOptionName` when loading.
2. **Charging an appointment skips the "register closed" check.** The gate lives only on adding an item (`ui/pos/CartActions.kt:173-186`); the Agenda › Cobrar path loads a saved ticket and opens the pay sheet with no check (`ReportsNavGraph.kt:115-123`, `HomeScreen.kt:257`), and `finalizeOrder` has none. Appointments booked yesterday are charged first thing in the morning — the cash lands outside any shift, so Close register will not match. Fix: run `registerBlocksSale()` before `loadSavedOrderIntoCart` on the Cobrar tap (owner → Abrir caja, then continue). (money, not demo-blocking)
3. **The booked service is locked like a kitchen dish**: changing it (Corte de dama → Corte + cepillado) needs the owner PIN and a reason list that offers "Error de cocina" (`VoidPinDialog.kt:230-234`, `CheckoutBreakdownScreen.kt:597`). Nothing was "sent" anywhere for a salon. Fix: for services, do not mark loaded lines as sent (or allow the − / delete without PIN), and drop the kitchen reason when `!isRestaurantType`.
4. No way to add an add-on to the booked service at the register; extras only as separate lines (§4.3). Possible confusion for "lavado / cepillado" style extras. Fix: let a tap on the booked line reopen its options sheet.
5. Pay screen shows no appointment context (time, service duration) and Sale complete offers no "Agendar la próxima" — a natural salon/vet step. Idea, not a bug (see question).
6. Ventas row of a paid appointment shows only the payment time, not the appointment time (`ServicesTransactionsScreen.kt:459`). Small.
