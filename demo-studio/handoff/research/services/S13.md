## 1. What differs for services, who, where
- **Clients come from the agenda.** A booking's "¿Para quién? / Para quem? / For who?" row opens the same client picker as the pay screen
  (`ui/screens/services/BookingScreen.kt:176-189`); "+ Nuevo" there creates the client and attaches it. So a salon's list fills up from bookings.
- Owner phone: panel row "Clientes · 8 clientes" (`HomeScreen.kt:1680-1712`, `home_clientes_count`). Employee phone: More › "Clientes · Ver y
  agregar clientes"; edit only with "Editar clientes". Counter tablet: through the pay-screen / booking picker only.
- **Client history** = the customer page (`ui/screens/customers/CustomerPage.kt:107-217`): WhatsApp, ID, address, "Visitas", "Última visita",
  then "Compras" — one row per PAID / refunded sale: "#27", date, "Vendido por: Ana", badge if refunded, amount. **Bookings (open tickets)
  are left out** (`sync/CustomerPurchases.visible` keeps PAID, COMPLETED and the refund statuses only), so the page shows no upcoming
  appointment and no "next visit". The rows show no service name: what was done is seen only by opening the sale (its receipt lists the services
  and the booking note as an info line).
- **Trade-specific fields (pet name, plate, bike model): not found in code as fields.** Searched `mascota|placa|plate|pet|vehic` in
  `ui/screens/customers`, `data/Customer.kt` and the guide catalogue: nothing. What exists:
  1. **Custom fields**: in the client form, "Avanzado › + Agregar campo" (`ui/components/CustomFieldsSection.kt`) lets the owner name a
     field ("Mascota", "Raza", "Placa", "Moto"). It is SHOP-WIDE (every client form shows it; removing it asks
     "¿Eliminar "Mascota" de todos los registros? Se perderán los valores ya ingresados.") and a filled one is promoted above the Avanzado box.
  2. **"Notas"** (built-in, inside Avanzado) and **"Contacto de emergencia"**, "Cumpleaños".
  3. The booking's own **"Nota"** field (`BookingScreen.kt:192-199`, per visit: "Max, refuerzo antirrábica").
  But custom fields and Notas are shown **only inside the edit form**: the customer page, the list, the agenda row, the booking and the
  receipt never show them, and the search matches name and WhatsApp only (`CustomerCrmScreen.kt:295-297`), not a plate.

## 6. UX/UI problems (verified)
1. **BLOCKS A DEMO (vet / workshop): what the owner writes about a client (custom fields like "Mascota" / "Placa", and "Notas") is shown nowhere
   but the edit form.** `CustomerPageContent` draws WhatsApp, ID, address, visits, last visit only (`CustomerPage.kt:157-170`); custom values are
   loaded only by the form (`CustomerCrmScreen.kt:792`). Fix: show filled Notas and custom fields on the page under the details.
2. Search matches name and WhatsApp only (`CustomerCrmScreen.kt:295-297`): a workshop cannot find a client by plate. Fix: also match custom field values.
3. The page has no upcoming appointment: bookings are excluded from "Compras" (`sync/CustomerPurchases.visible`) and nothing else lists them.
   For services the most useful line is "Próxima cita: jue 23 oct, 10:00". Fix: a "Próxima cita" row from the open bookings with `scheduledFor`.
4. Purchase rows say "#27" with no service name (`CustomerPage.kt:203`). Same row already flagged as M2 ("Venta #27") — still not fixed here; for
   services also add the first service ("Corte de dama y 1 más"), the same rule as the sales list.
5. The agenda and the services sales list search by `phoneNumber`, which no client ever gets (see S8 problem 1).
