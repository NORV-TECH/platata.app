## 1. What differs for services, who, where

- **The door is different.** A services shop has no generic sales list. `ServicesRules.transactionsDestination = AGENDA`
  (`data/business/ServicesRules.kt:54`), so the bottom tab "Ventas" opens `ServicesTransactionsScreen`
  (`ui/navigation/ReportsNavGraph.kt:56-65`), which **opens on the Agenda half** (`ownTab = 1`,
  `ui/screens/transactions/ServicesTransactionsScreen.kt:98`). The owner must tap the "Ventas" top tab first.
- **Per device:**
  - Owner phone: bottom tab "Ventas" → top tab "Ventas" → tap a row → sale opens as a dialog (`SaleDetailHost(asDialog = true)`, :322-327).
  - Employee phone (Mini POS): its own tab row is Servicios · Productos · Ventas · Agenda (`ui/screens/onboarding/MiniPosSellScreen.kt:604-608`);
    "Ventas" renders the SAME services list without its header (`renderServicesTx(0)`, :682). Refund needs "Devolver" (`canRefund`).
  - Counter tablet (MamaPos): tabs Servicios · Productos · Ventas · Agenda (`ui/screens/mamapos/MamaPosScreen.kt:820-830`), but its
    "Ventas" tab is the **generic** grid of sale cards (`TransactionsScreen(useGridLayout = true, forcedTab = 0)`, :1206-1224), not the
    services list; a card opens the same sale host inline (`asDialog = false`, :1555-1559).
- Trades: no difference between beauty / pets / vehicles / repairs in this feature (no `rules.` or trade read in the refund code).
- Services have no fiado (`fiadoEnabled = false`), so the tab-refund line and the "Also take $X off the tab" box never show.
- A services sale can carry two charges the restaurant one does not: the **"A domicilio" / "Recogen y entregan" trip charge**
  (a where-mode fee, `ui/pos/AutoRules.kt:68-90`, stored as an ordinary `order_fees` row) and, in US/CA, a **card tip**
  (`ServicesRules.tipDefaultOn = true`). A partial refund spreads over them; the grey note under the item list says so
  ("La devolución reparte los descuentos y cargos de la venta." / "La propina no entra en una devolución parcial…", `TransactionsScreen.kt:1789-1806`).
- A sale may mix a service and a product (shampoo, esmalte). Stock goes back only on a FULL refund on the device that made the sale (retail S8 §1 applies).

## 6. UX/UI problems (verified)

1. **Search by phone never finds anyone.** The list matches `customer.phoneNumber` (ServicesTransactionsScreen.kt:208, :282), but the
   client form and every other writer save the number in `whatsappNumber` and write `phoneNumber = null` (customers/CustomerCrmScreen.kt:858-860;
   no other writer found). The placeholder promises "Por nombre o teléfono…". Fix: match `whatsappNumber` digits too.
2. "Ventas" opens on the Agenda half every time (`ownTab = 1`, :98), so the bottom tab named "Ventas" shows bookings. Possible confusion
   in a refund demo; fix: remember the last half, or name the bottom tab "Agenda".
3. The top-left icon is an X with no label (:123-125) on a bottom-tab page; every other list uses the back arrow (G-08). Fix: back arrow + `common_back`.
4. Rows show no sale number, so "Venta #27" (receipt, sale screen, Reports) can't be matched or searched here. Fix: add "#27" to the second line and let search match it.
5. A cancelled appointment shows its full price in bold like a sale (:467-472) and opens a "Venta #N" screen for something never charged.
   Fix: grey/struck amount and the word "Cita cancelada".
6. Amounts use the global `formatCurrency(x)` without the shop currency (:411, :469, :475) — same bug class as PHONEFIX-1 (possible wrong
   symbol right after a business switch). Small.
7. The "Monto" field shows the raw "25000" (no grouping), unlike every other money box (`TransactionsScreen.kt:1904-1925`, `filterDecimalInput`
   without `MoneyVisualTransformation`). Small; hits every type.
8. Counter tablet's "Ventas" is the generic grid, the phones show the services list — two looks for one shop. Small.
