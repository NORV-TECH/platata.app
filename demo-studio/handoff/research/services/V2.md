# V2 — Edit prices and options (SERVICES)

Code read at commit `17d519ac` (branch sim/usa-canada). Paths under `app/src/main/java/com/example/`. Nothing was run on a phone.

## 1. What it does, who, where
- After the setup walk, the owner changes what a service costs and what comes with it: rename, new price, a price per choice ("Corto / Medio / Largo"), and the options (included / charges more / pick one, minutes). Owner's phone only.
- Doors:
  - **"Mis servicios"** page (`ui/screens/items/ServicesMenuScreen.kt`). Only door: the till's **"Editar"** button turns on the amber **"Editando"** bar, whose link **"Mis servicios ›"** opens it (`ui/screens/home/HomeScreen.kt:907-914, 1990-2050`). Shown only on the owner phone with no open ticket. The panel has no Services row (F-01).
  - A service row (or a tap on a tile while "Editando", or a long-press on a tile) opens **"Editar servicio"** (`ui/screens/services/ServiceEditScreen.kt`) for any product of type SERVICE (`ui/navigation/CatalogNavGraph.kt:150-163`).
  - **"Adiciones"** card → the add-ons list (`ui/screens/items/CategoryHubScreen.kt`, tab 1) → add-on editor (`ui/screens/modifiers/ModifiersManagementScreen.kt`).
  - **"Opciones"** page (`OptionsPickerPage.kt` + `OptionsPickerScreen` in `ItemsScreen.kt:1558`) is reached ONLY from the generic item form (`ItemEditorScreen`), i.e. for a NEW hand-made service ("Mi oficio no está" / "Crear el mío") or for a PRODUCT of the Productos tab. An existing service never reaches it (Editar servicio has no Options row).
- Counter tablet / employee phone: cannot edit. They get the new prices and options through the reference sync and show them at the till (shared `ProductSheetHost`).
- Price modes: `Product.servicePriceMode` FIXED / FROM ("Desde") / ASK ("En la caja") (`sync/ServicePriceMode.kt`). **Set only in the setup bridge** (`ui/pos/GuideActions.kt:537-555`); Editar servicio cannot change it (`CatalogActions.kt:124-127` carries it unchanged).
- Trades: same screens for all 41 trades. Only differences are the data: which services have a price-by-choice (vet "Vacunación", nails "Uñas acrílicas", salon "Balayage" / "Cepillado") and which options are included vs charged. Every researched service in the four demo trades has at least one option (checked in the json).

## 2. Setup before the demo
- Services shop, setup walk finished (services picked, prices given). Each walked service gets its researched options as option sets (`GuideActions.kt:581, 649-720`). The trade's researched PRODUCTS are also added to the Productos tab (`GuideActions.kt` ~588; brand names like "Olaplex N°3…", "Masglo", "Bravecto" — rename or avoid them on camera; Taller de motos products are generic).
- No add-ons (modifier sets) exist by default. Services get NO add-on ideas (`ServicesRules.showsModifierTemplates = false`), so the ideas page shows only "Tu propia adición".
- Factory price modes: FIXED unless picked otherwise in the bridge.

## 3. Country differences
- **Colombia:** Editar servicio shows three price pills built around the service's CURRENT price (−20 %, current, +20 %, rounded to 1.000) + "Otro" (`data/catalog/GuideLogic.kt:30-41`, `ServiceEditScreen.kt:138`). Add-on pills on "cobra más" (+$ …).
- **Everywhere else (MX PE CL EC AR PA BR US CA):** no pills (`PriceSuggestions.mayShowResearchedPrices` is CO only); just an empty "¿Cuánto cobras?" box — and it opens EMPTY (problem 2). Setup itself started as one list (CU-R08).
- Money: CO "$ 45.000", MX "$450.00", PE "S/ 45.00", CL "$45.000", EC "$45,00", AR "$ 4.500,00", PA/US "$45.00", CA "$45.00", BR "R$ 45,00" (`functions/test-vectors/money-format.json`; PA is now "$" since FIX-3).
- Language: service names and researched option names are written in the language of the walk; option VALUES of product axes (Opciones page "Sugerencias") stay raw Spanish ("Brillante / Mate") in BR / US / CA (`GuideActions.kt:236-253`, known corpus limit).
- Tips are not part of this feature.

## 6. UX/UI problems
1. **BLOCKS A DEMO — "Adiciones" never appear at the till for any researched service.** The tap goes option sheet first and returns (`ui/pos/CartActions.kt:478-482`); the option sheet reads only option sets (`OptionSelectionSheet.kt:97`), so a modifier set linked to "Corte de dama" is never offered. Every researched service in the 4 demo trades has options. Fix: show the service's add-ons inside the option sheet (or chain the modifier sheet after it).
2. **BLOCKS A DEMO outside Colombia — the price box opens empty.** `custom` starts "" and no pills exist (`ServiceEditScreen.kt:104`, `PricePicker.kt:84`): a Mexican/Brazilian owner can't see the current price on "Editar servicio". Fix: seed the box with `seedMoneyField(basePrice)` when there are no pills.
3. **Phone Back discards edits silently, the arrow saves.** No `BackHandler` in `ServiceEditScreen.kt` (top-bar arrow calls `commit()` at :165; gesture just pops). Fix: one rule — BackHandler that commits (or asks).
4. **An "En la caja" (ASK) service can't be fixed here.** No price-mode control; a typed price is stored but the till keeps asking and the list keeps "En la caja" (`CartActions.kt:473`, `ServicesMenuRule.kt:51`). Same for "Desde". Only a full trade re-walk changes it. Fix: Fijo / Desde / En la caja chips on Editar servicio.
5. **Restaurant words in the services add-on screens.** "Salsas, extras o término para un plato", "Aún en ningún plato", "Vinculada a N platos", "¿En qué platos?", "Platos para…", "Primero agrega platos…" (`addon_empty_line`, `mod_not_on_any_dish`, `your_menu_linked_items_count`, `modmgmt_on_which_dishes`, `mod_items_for`, `modmgmt_add_dishes_first`; also pt). Fix: services variants ("servicio").
6. **"Tus opciones" floods with the walk's option sets.** It lists every `item_option_sets` row (`ItemsScreen.kt:1583-1593`, `PosDao.kt:1487`), and the walk writes one set per option per service: ~50 rows for a 12-service salon, "Lavado" ×4, "Largo del cabello" ×5, ordered by key. "Lavado" is then refused as a new name ("Ya tienes…"). Fix: show only sets made on this page / not attached to a researched service, deduped by name.
7. **"Sugerencias" for a service are PRODUCT axes** (presentación 250/500 ml, marca…) with brand product names in the grey "who" line ("Olaplex N°3…") (`GuideActions.kt:255-285` reads `oficio.productos`). Fix: for a SERVICE, suggest the trade's service option sets (e.g. "Largo del cabello").
8. small (possible) — A hand-made service given an option set asks the same choice twice at the till: choice sheet (generated variations) then the option sheet with the same set (`ProductSheetHost.kt:199-216`, `CartActions.kt:540-543`). Likely hits products too. Fix: skip sets that already became variations.
9. small — A new hand-made service with options gets every choice at ONE price: the item form has no per-choice box outside restaurants (`ItemsScreen.kt:1196`); the owner must save, reopen, then price each choice. Fix: show `DishSizePrices` for services too.
10. small — Options of an existing service can't be changed (Editar servicio has no "Opciones" row); choices can only be repriced. Fix: add the row (→ Opciones page).
11. small — Price boxes show raw "45000" (no `MoneyVisualTransformation`) in `ServiceEditScreen.kt:216`, `PricePicker.kt:84`, `BridgeOptionEditor.kt:182, 276`. Same class as round-3 item 18; still not fixed here.
12. small — Words: "Eliminar artículo" / "Excluir Item" / "Delete Item" on a service (`items_delete_item`); pt "Escreve um nome" (tu form, should be "Escreva"); Opciones lede "Un producto varía…" on a service.
13. small (possible) — Option editor's minute chips (5 chips in a non-wrapping Row, `BridgeOptionEditor.kt:241-249`) and percent chips may clip at 360dp. Fix: FlowRow.
14. small — Option editor header is a hand-made Row, not `SumaTopBar`; the "✕" next to each pick-one value has no screen-reader label (`BridgeOptionEditor.kt:106-118, 196`).
15. small — Paper "Mis servicios" opens Material "Editar servicio" and "Adiciones": visual jump.
