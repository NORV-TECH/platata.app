# V5 — Mover o cancelar una cita (reschedule, cancel, no-show, what the client is told)

Code read: /home/claude/app-head @ `17d519ac` (branch sim/usa-canada). Paths under `app/src/main/java/com/example/`.
No shared S-file covers this (it is services-only). Booking a NEW appointment is V4; charging it is V6.

## 1. What it does, who, which device
- A booked appointment (an open ticket with a "¿Cuándo viene?" / "¿Cuándo está listo?" date) is opened from the **Agenda** and the owner can: **Cobrar** (V6), **Reprogramar** (move day/hour), **No asistió** (no-show), **Cancelar cita**. A moved time can be sent to the client with "Guardar y avisar por WhatsApp".
- Owner phone: Ventas tab › "Agenda" › row → full page `AppointmentDetailScreen` (route `appointment_detail/{orderId}`, `ui/navigation/ReportsNavGraph.kt:106-124`).
- Employee phone (Mini POS): its own Agenda tab (`ServicesTransactionsScreen` with `showChrome=false`) → same detail route (`ui/screens/onboarding/MiniPosSellScreen.kt:646-661`).
- Counter tablet (MamaPos): Agenda inside the tablet → the same detail drawn as a full overlay over the whole tablet (`ui/screens/mamapos/MamaPosScreen.kt:1506-1519`).
- Also opened by a tap on an online-booking notification (`ui/app/NavigationEventEffects.kt:59-66`).
- **Trade differences** (only via the booking "kind", `data/ScheduleKind.kt`): beauty / pets (CITA trades: peluquería, uñas, veterinaria…) store an arrival time → row label "Viene", picker "¿Cuándo viene?". Vehicles / repairs (ORDEN trades: taller-motos…) store a ready date → row label "Domicilio" (es!) / "Entrega" (pt) / "Delivery" (en), picker "¿Cuándo está listo?" and a "Sin hora · todo el día" slot. Same four buttons for both (see problems 2 and 3).

## 2. Setup before the demo
- A services business with the setup finished (V1-V3) and at least two appointments booked (V4) for TODAY (so "No asistió" shows) and one for a future day (so only "Cancelar" shows). A booking always has a customer (the save refuses one without, `ui/pos/SavedTicketActions.kt:112`).

## 3. Country differences
Flow identical in every country. Only the time/date text changes, and it follows the APP LANGUAGE, not the country (`ui/screens/services/WhenPicker.kt:73-90, 131-150`):
- es (CO MX PE CL EC AR PA, US-es): "3:00 p. m.", day "jue 23 de oct", "Hoy", "Mañana".
- pt-BR (BR): "15:00", day "qui 23/10", "Hoje", "Amanhã".
- en (US, CA): "3:00 PM", day "Thu 23 Oct", "Today", "Tomorrow".
- Slot grid is fixed 8:00–20:00 every 15 min in every country (`WhenPicker.kt:46-48`); footer "Abres 8:00 a. m. – 8:00 p. m." / "Aberto 8:00 – 20:00" / "Open 8:00 a. m. – 8:00 p. m." (en uses "a. m." while the slots say "AM" — small, V4).
- Amount on the agenda row: CO "$ 45.000", MX "$450.00", PE "S/ 45.00", CL "$45.000", EC "$45,00", AR "$ 4.500,00", PA "$45.00" (USD now writes "$", FIX-3), BR "R$ 45,00", US/CA "$45.00".
- Nothing about cancel / reschedule is country-gated. Online bookings exist wherever the online store opens (S20).

## 6. UX/UI problems (verified in code)
1. **Staff phone without "Cancelar recibos": Cancel / No-show silently do nothing.** The buttons show, the dialog confirms, `cancelAppointment` returns early (`AppointmentActions.kt:84`), the screen closes and the booking is still there — no message. Fix: hide the two buttons when `canCancelReceipt` is false, or show "Pídele al dueño".
2. **ORDEN trades (taller-motos, repairs) get salon words.** Row label `sx_delivery` es = "Domicilio" (means home delivery) for a ready date; buttons/dialogs say "Cancelar cita" / "¿Cancelar esta cita?"; "No asistió" + "No llegó" for a bike that is in the shop. Fix: es "Entrega", and "Cancelar orden" / "No vino a recogerla" when `kind == ORDEN`.
3. **ORDEN overdue = cannot cancel, only "No asistió" which voids the job with nothing charged** (`AppointmentDetailScreen.kt:186-213`, `late` hides Cancelar). A moto finished but not picked up has no honest exit except Cobrar or Reprogramar. Fix: for ORDEN keep "Cancelar orden" when late and drop "No asistió" (or rename it).
4. **"Avisar por WhatsApp" message is not written for the client**: it is the client's own name and own phone plus the time, no shop name, no "your appointment moved" (`:408`), and it goes through the share sheet instead of the client's chat (`:390-396`). Fix: "Hola Laura, tu cita en <negocio> quedó para mañana jueves 23 a las 4:00 p. m." in the SHOP language (ShopLanguageText) and open WhatsApp straight to the client's number (`WhatsappOpen`, like the receipt).
5. **Cancel / no-show tell the client nothing** and offer no "avisar" button. Fix: after the confirm, offer "Avisarle por WhatsApp" with "Tu cita del jueves 4:00 p. m. quedó cancelada".
6. No-show and cancel are stored the same (CANCELLED, both "Anulada" in Ventas) — the owner can never count no-shows, though the code comment promises he "can see it keeps happening" (`AppointmentActions.kt:68`). Fix: keep a reason ("no asistió") on the order or a no-show badge. Possible schema change — ask Monti.
7. Detail page hides price, where (A domicilio / En el local) and note; and shows only the first service when the ticket has two (`:95`, `:169-174`). Fix: list every line with its price and the where mode.
8. Two ways to open the picker on one page ("Reprogramar" button and "Cambiar" in the summary row) and a "Guardar" that saves nothing when nothing changed. Fix: drop "Reprogramar" (or the Cambiar link), and say "Listo" when nothing changed.
9. No feedback after a save, cancel or no-show: the page just closes (`:315`, `:368`, `:380`). Fix: snackbar "Movida a mañana 4:00 p. m." / "Cita cancelada · Deshacer".
10. Clash warning only for the SAME start minute (`bookedByDay` maps start minute only, `:118-128`, `:133`): moving a 40-min cut to 3:15 when another starts at 3:00 says nothing. Fix: compare time ranges using the durations (shared with V4).
11. Agenda search finds phone only in `phoneNumber` (`ServicesTransactionsScreen.kt:208`); an online client with only WhatsApp is not found by number, and the empty text says "Nadie con ese nombre." even for a number search. Small. Fix: also match `whatsappNumber`; "Nadie encontrado".
12. Agenda top bar uses an ✕ (`:123-125`) and the detail uses a raw `TopAppBar` (`AppointmentDetailScreen.kt:143`), against G-08 (back arrow, `SumaTopBar`). Small.
13. pt-BR mixes three nouns for the same thing: "reserva" (buttons, clash), "agendamento" (cancel-failed dialog), "Agenda/agendado". Small. Fix: one word ("agendamento").
14. While an appointment is being charged (loaded into the sale), it disappears from the Agenda (`lifecycleState = ACTIVE`, `SavedTicketActions.kt:636`) until it is paid or "Salir" is tapped; a cashier who backs out of the pay screen with "‹" sees it gone. Possible confusion. Fix: list ACTIVE ones too with "En caja".
